## 当前范围

整理 `rl_exp/out/` 的存量产物，并让后续诊断在运行结束时完成归属、保留或清理。目标是能按问题找到适用证据，保住必要输入和失败对照，停止无主产物持续堆积。

本项当前仅建单，整理尚未执行。范围包括产物、生产脚本、实际消费者、路径引用、Git 边界及收尾规则；不改变机器人构型、驱动参数、实验判据或已有诊断结论，不以目录整理代替原专项验收。

协调入口：[机体与驱动总项](lizard2-body-drive-candidate.md)、[候选接线](lizard2-candidate-wiring.md)、[限位与 PD 验证](lizard2-restored-limits-pd-validation.md)。迁移其依赖前确认使用状态；正在写入的目录不得搬移或清理，未完成实验仍归原事项。

盘点读数、迁移结果和审核结论归 `acceptance/records/`，有实际证据后创建记录并补本项 `evidence` 指针。本项只维护当前动作，不复制实验读数或编造已完成记录。

## 分类与保留原则

| 类别 | 保留依据 | 处理目标 |
|---|---|---|
| 当前依赖 | 活跃事项、代码或后续实验实际消费 | 保留完整依赖，建立明确入口 |
| 可复用诊断 | 回答明确问题，资产、工况、配置与代码身份可核实 | 保留报告、必要原始数据和复读入口 |
| 历史对照 | 缺陷复现、修复前后对照、关键反例或旧结论的唯一依据 | 按问题归档，标明适用边界和替代关系 |
| 可再生成输出 | 可从已保存输入重新生成，且不承载独立证据 | 实际验证再生成后清理；有独立观察价值的保留 |
| 无效或重复尝试 | 无独立诊断价值、无保留依赖且内容可确认 | 经清单核验后清理 |

失败不等于无价值，较新或名为 final 不等于有效；日期、文件名和文本搜索无命中均不能单独作为删除依据。未判定条目保持待处理，必须有责任人与下一步。

## 目标落点与复用

- 运行产物按 `rl_exp/out/runs/<主题>/<运行编号>/`、`archive/<主题>/<运行编号>/`、`tmp/` 分流；日期进入运行编号或元数据。旧路径分批迁移，不要求一次全改。
- 沿用已有 manifest、哈希与绑定工具，补一个轻量索引，只记身份、用途、位置、依赖、关联事项/验收记录和保留理由，不建立第二份结果账本。具体索引路径在盘点后确定并补入 `landing`。
- 诊断索引须能回答“验证什么、不能证明什么、对应何种资产/配置/工况、怎样读取与复跑、是否仍适用”。复用前核对这些前提；输入变化只补受影响检查，不能将旧资产或旧驱动证据外推。
- 源码、配置、索引、验收记录及必要的最小回归样本纳入 Git；运行输出默认忽略。已跟踪产物逐项处理，必要的长期诊断基准迁出临时输出区，不自动升级为正式机器人资产。
- 唯一或昂贵的证据包注明存储位置、完整性校验与恢复方式；本机单副本如实标记。建立可靠恢复方式前不得清掉唯一证据，忽略规则不等于备份。

## 下一步

1. **盘点与处置清单——整理执行者负责。** 枚举现存目录及顶层散文件，记录大小、内容哈希、Git 状态、生产者、实际消费者、关联事项、保留原因和拟处理动作。检查代码、配置、报告、验收记录及相对/绝对资源引用，展开保留集合的传递依赖。清单和读数写入验收记录及其引用附件；执行前复核新增文件和仍在运行的生产者。
2. **先管新增——整理执行者与诊断脚本维护者负责。** 确定最小索引与统一目录入口，优先复用现有工具；新运行登记主题、关联事项与输入身份，结束时判定继续使用、保留、归档或清理。规则落在诊断子系统文档与实际生产入口，FILEMAP 只留路由；未覆盖入口列为明确未完动作。保持新运行不覆盖旧证据，当前有效入口须经核实后显式切换。
3. **分批迁移——整理执行者负责，消费者维护者核对。** 每批先生成旧/新路径映射、内容校验和回退步骤，确认完整输入依赖与运行状态，再迁移资产包、报告和日志。修复写死路径及活跃复读入口；历史证据正文保留原身份，通过映射或独立迁移记录解释位置变化。不得批量改写旧 JSON 的路径/哈希冒充原始证据；涉及公开 API 时遵守既有弃用规则。
4. **验证与清理——整理执行者负责。** 核对迁移前后保留内容及依赖完整性，实际运行代表性报告读取、网格解析、离线复验与必要的运行时消费者；涉及压缩归档时验证解包恢复和复读。验证完成且清理集合不含唯一证据、活跃输入或待判定项后，再移除旧副本与无效尝试。先处理无用整包，再按内容身份处理重复资产；需独立修改的副本不共享可写文件。删除前验证绝对路径位于批准范围，隔离目录必须有清理出口，不得成为新垃圾堆。
5. **落实持续收尾——各次实验执行者负责，整理执行者交付机制。** 每次运行结束更新归属和保留决定；保留须有用途，待判定须有责任人和动作。容量或积压超限只报告并触发人工判断，不按日期或预算自动删证据。新机制若增加闸门，须对应本次实际缺陷并有破坏测试，不能只检字段齐全。
6. **交审核——整理执行者负责。** 运行相关检查与仓库闸门，将实际结果写入验收记录，同次更新事项证据指针；完成后置 `pending_review`，`next` 指向不带执笔历史的新上下文审核者。新建本 work 不代表以上动作已完成。

## 关闭条件

- **审核者与输入**：不带执行历史的新上下文读取实际落点、处置清单、迁移映射、内容校验、复读命令、消费者验证与恢复证据；独立检查，不依赖执行者总结。
- **清单闭合**：存量及整理期间新增条目均有明确处置；未分类、仍在写入、待确认依赖不得算完成。确需后续承接的动作同次用脚手架建立新事项并从本项迁移，不能随关闭消失。
- **复用成立**：从实际诊断问题能够定位适用报告、输入与工况边界，并成功读取和运行代表性复读入口；关键失败对照仍可用。不得仅以索引存在或路径字符串一致判定通过。
- **迁移与恢复成立**：保留证据内容身份可核实，实际消费者无断链；每类迁移或归档方式均有恢复验证。原结论与哈希绑定未被静默改写，唯一证据未丢失。
- **新增不再失管**：真实新运行能按新布局登记并完成收尾；暂存失败、路径断裂或依赖缺失等已发现风险有对应拒绝或保留行为验证。若有回归修复，证明修复前失败、修复后通过。
- **Git 与交付**：提交边界明确，运行输出不误入仓；必要基准和最小回归样本可获取。机制交诊断脚本维护者，日常收尾交实验执行者；验收记录说明本机独有证据与复现限制。节省空间多少不作为通过条件。
- **结果处理**：通过审核后关闭；可修缺口退 in_progress，仅用户能解决的缺口置 blocked。
