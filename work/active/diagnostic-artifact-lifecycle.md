## 当前范围

整理两个输出根及生产者发现的其它落点，保住必要输入、失败对照与复读入口；通过解耦和运行收尾停止无主产物堆积。

用户已撤销“不删除、不搬活跃链”限制，要求实际解耦、合并、重构和删除。已接通的依赖按批迁移，已替代材料清理；其它消费者、混合子树和运行收尾继续推进，不永久留置 pending。处置见最新 evidence；机器人、驱动参数与诊断判据归原专项。

协调入口：[机体与驱动总项](lizard2-body-drive-candidate.md)、[候选接线](lizard2-candidate-wiring.md)、[限位与 PD 验证](lizard2-restored-limits-pd-validation.md)。按实际读写关系确定迁移批次；正在写入的目录先协调停写，接通消费者并复验后迁移，未完成实验仍归原事项。

记录按自身边界取用，局部实施不代表全事项关闭。

## 分类与保留原则

| 类别 | 保留依据 | 处理目标 |
|---|---|---|
| 当前依赖 | 活跃事项、代码或后续实验实际消费 | 保留完整依赖，建立明确入口 |
| 可复用诊断 | 回答明确问题，资产、工况、配置与代码身份可核实 | 保留报告、必要原始数据和复读入口 |
| 历史对照 | 缺陷复现、修复前后对照、关键反例或旧结论的唯一依据 | 按问题归档，标明适用边界和替代关系 |
| 可再生成输出 | 可从已保存输入重新生成，且不承载独立证据 | 实际验证再生成后清理；有独立观察价值的保留 |
| 无效或重复尝试 | 无独立诊断价值、无保留依赖且内容可确认 | 经清单核验后清理 |

失败不等于无价值，较新或名为 final 不等于有效；日期、文件名和文本搜索无命中均不能单独作为删除依据。未判定条目保持待处理，必须有责任人与下一步。

## 目标落点与复用

- 运行产物按 `rl_exp/out/runs/<主题>/<运行编号>/`、`archive/<主题>/<运行编号>/`、`tmp/` 分流；日期进入运行编号或元数据。旧路径分批迁移，不要求一次全改。
- 复用 manifest、绑定工具与既有索引，记录身份、用途、位置、依赖、归属和保留理由；结果唯一归验收记录。
- 诊断索引须能回答“验证什么、不能证明什么、对应何种资产/配置/工况、怎样读取与复跑、是否仍适用”。复用前核对这些前提；输入变化只补受影响检查，不能将旧资产或旧驱动证据外推。
- 源码、配置、索引、验收记录及必要的最小回归样本纳入 Git；运行输出默认忽略。已跟踪产物逐项处理，必要的长期诊断基准迁出临时输出区，不自动升级为正式机器人资产。
- 唯一或昂贵证据注明存储、校验及恢复方式；核验恢复后清原副本，外部备份与本机保留分开标记。

## 迁移前必须补齐

以下由整理执行者与脚本维护者按受影响链落实，已完成切片见最新 `evidence`；其它链的缺口不阻止已验证批次迁移和清理，文档修订不能代替行为证明。

| 缺口 | 必须落实的动作与验收 |
|---|---|
| 消费者不读取迁移映射 | 接通 `local_path_view._load`、`palm_spatial_runtime.check_build` 及传递依赖的实际定位机制，保持身份和授权边界，缺映射或摘要不符必须拒绝。迁移验收在旧根及其链接均不可访问的隔离环境中调用真实消费者；不得借旧副本、junction 或原机器绝对路径通过。原路径授权不能简单删除以迁就搬迁。 |
| 检出可能改变绑定字节 | 将证据字节保护随目标路径迁移，核对目标有效 attributes；在独立临时仓/检出目录按目标布局执行 add、commit、重新检出，覆盖 `core.autocrlf=true/false`，逐文件比较原始、入库、检出字节与绑定摘要，运行恢复后的消费者。不能只核搬迁后的工作树。 |
| 同 label 覆盖旧输出 | 纳入 `diagnose_support.py` 及其输出根，采用不可覆盖的目录创建和写入流程。隔离样本通过真实生产写入路径重复同名运行，第二次须在覆盖前明确拒绝，旧目录所有文件的内容、数量和摘要不变；覆盖报告与摘要写入，不能只单测 mkdir。 |
| 优化模式绕过身份校验 | 审计本次保留/迁移链的身份校验，将必要 `assert` 改为不可优化掉的显式拒绝；若某入口暂不支持优化模式，须在读写前显式拒绝并限定复用范围。普通模式、`-O`、`PYTHONOPTIMIZE=1/2` 均验证错误身份拒绝且无输出写入，正常身份按声明支持范围验证。 |
| 忽略规则与跟踪状态混淆 | 覆盖两个输出根并修正“一切 dump 可再生成”的注释，逐项决定已跟踪产物保留或迁出索引；解除跟踪前落实恢复位置，不删本机唯一证据。用实际暂存状态和忽略检查验证必要基准仍可检出、运行产物不会误入库。 |

每项回归须先保存修复前的失败对照，再证明修复后通过；失败指行为违反上述要求，不以命令是否返回零代替判定。隔离样本不得触碰现存证据，结果归验收记录。

## 下一步

1. **盘点——整理执行者负责。** 枚举目录与散文件，记录大小、哈希、Git 状态、生产者、消费者、关联事项、保留理由和拟处理动作。检查代码、配置、报告、验收记录与资源引用，展开传递依赖。清单归验收记录；执行前刷新新增文件及运行状态。
2. **管住新增——整理执行者与脚本维护者负责。** 按目标落点交付索引、生产入口和子系统规则，FILEMAP 只留路由；新运行登记主题、事项与输入身份，当前有效入口经核实后显式切换。未覆盖入口列为未完动作。
3. **分批迁移——整理执行者负责，消费者维护者核对。** 每批准备路径映射、校验和回退步骤，按前置表接通消费者。历史 JSON 保持原身份，位置变化另记；不得改写路径/哈希冒充原证据，公开 API 遵守弃用规则。
4. **验证后清理——整理执行者负责。** 按前置表验证报告读取、网格解析、离线复验及必要运行时消费者；压缩包须解包复读。确认无唯一证据、活跃输入或待判定项后清理旧副本。先清无用整包，再处理重复资产；可独立修改的副本不共享可写文件。删除前核绝对路径范围，隔离目录须有清理出口。
5. **日常收尾——实验执行者负责。** 结束时更新归属及保留、归档或清理决定；待判定须有责任人和动作。超限只报告，不按日期或预算自动删除。新增闸门须对应真实缺陷并有破坏测试。
6. **交审核——整理执行者负责。** 跑相关检查与仓库闸门，结果归记录并同次更新证据指针；完成后置 `pending_review`，由 `next` 点名新上下文审核者。

## 关闭条件

- **审核者与输入**：不带执行历史的新上下文读取实际落点、处置清单、迁移映射、内容校验、复读命令、消费者验证与恢复证据；独立检查，不依赖执行者总结。
- **清单闭合**：存量与新增均有处置；未分类、仍在写入、依赖待确认不得算完成。后续动作同次用脚手架建新事项承接，不能随关闭消失。
- **复用成立**：从实际诊断问题能够定位适用报告、输入与工况边界，并成功读取和运行代表性复读入口；关键失败对照仍可用。不得仅以索引存在或路径字符串一致判定通过。
- **迁移与恢复成立**：保留证据内容身份可核实，实际消费者无断链；每类迁移或归档方式均有恢复验证。旧路径不可用时仍能复读，目标布局重新检出后字节及绑定不变。原结论与哈希绑定未被静默改写，唯一证据未丢失。
- **新增不再失管**：真实新运行能按新布局登记并完成收尾；暂存失败、路径断裂或依赖缺失等已发现风险有对应拒绝或保留行为验证。若有回归修复，证明修复前失败、修复后通过。
- **Git 与交付**：提交边界明确，运行输出不误入仓；必要基准和最小回归样本可获取。机制交诊断脚本维护者，日常收尾交实验执行者；验收记录说明本机独有证据与复现限制。节省空间多少不作为通过条件。
- **前置缺陷关闭**：“迁移前必须补齐”各项均有实际行为证据；同名拒写、优化模式拒错、两个输出根的治理以及必要样本的重新检出均不得以索引、规则声明或旧副本存在代替验证。
- **结果处理**：通过审核后关闭；可修缺口退 in_progress，仅用户能解决的缺口置 blocked。
