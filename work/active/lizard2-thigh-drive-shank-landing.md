## 当前范围

承接 `work/active/lizard2-learned-gait.md` 中的大腿参与、后腿折叠与小腿落地姿态专项；整体步态、身体与躯尾协调、转向及版本训练交接仍归总项。当前已进入诊断，未修改正式奖励、资产或配方，未启动新训练；本项未完成修复或独立审核。

用户反馈大腿 swing 基本不动、主要靠小腿拨动，后腿折起来，小腿落地时不接近垂直地面。已选定 v7 的策略复读对象，现场身份、几何核查、rollout、临时 clip 对照、训练阶段读数及解读边界统一见 `acceptance/records/2026-11-04-lizard2-shank-tilt-reach.md`。该 run 是否就是用户观察的问题现场及多视角录像仍待核对，不将开发配置直接当成策略训练配置，不宣称奖励或动作尺度已被证实为根因。

用户确认的目标分工：小腿本来就承担接地支撑；后腿主要靠大腿旋转推进；前腿主要靠用户所称的膝关节带动小腿拨动，并配合大腿旋转。期望小腿在落地时接近垂直地面，不要求整个步态周期始终竖直。大腿参与不足明确包含 swing；其推进作用仍须结合实际骨段、轴向与接触阶段测量，不能仅凭名称判断。

当前待证伪方向：swing 与 twist 的动作响应、刚度及阻尼是否限制有效运动；abduct 与 elbow/knee 是否代偿并形成后腿折叠；策略奖励和正则是否允许固定大腿、主要靠小腿推进。配置推算与 URDF 几何读数只作线索，数值及成立条件见验收记录；USD 轴向、动态支撑与因果对照尚未完成。

用户方向：小腿驱动力不应高于大腿；要求测试降低小腿（肘/膝）、提高大腿推进轴的驱动是否可行。三类参数性质不同，须分别比较，不统称增益变体：PD 刚度（及随之核定的阻尼）改变单位误差力矩与抗扰；动作 scale 改变单位 action 的目标位移，目标范围另受 clip 限定；力矩上限只改变最大可用力矩。调整载体与幅度尚未定案，须由探测比较后经用户选定；降低小腿任一参数须同时验证支撑不塌、腹部不触地。

执行约束：不把卡限位本身当作 swing 缺少周期运动的根因，不把放宽限位当作已定修复。用户提出的可视化范围调整仅用于几何观察，不视为正式资产、动作 clip 或新训练的修改批准；范围与 PPO 梯度解释见验收记录“限位与学习机制解释校正”。当前优先排查其他机制。

问题目标是有效推进与合理落地姿态。不能将小腿接地本身判错、强制改为仅足端支撑，或把统一增加大腿摆幅作为已定修复。落地阶段的小腿朝向奖励是候选手段；倾角容差、阶段窗口和权重尚未定案，对话中的示例数值不构成参数批准。

## 下一步

1. **补齐问题现场与推进轴映射（执行者）**：沿验收记录的 v7 run/checkpoint 复读入口核对它是否为用户问题现场，补多视角录像；按命令与步态阶段复读大腿参与不足、后腿折叠及小腿落地倾斜。在该机体上把“大腿旋转/膝关节”映射到实际骨段与轴，记录大腿水平及落地典型姿态下各轴（swing/abduct/twist/elbow 或 knee）的世界系朝向，以 USD 为准并与 URDF 比对。URDF 离线 FK 及破坏检查已有证据，本步补齐 USD、根体/胸部姿态及足端落点的未覆盖部分，区分仅 swing 可达与须多轴联动可达的落地姿态；倾角同时保留总量与前后向、横向分量。分别记录用户观察和测量证据，结果唯一归 `acceptance/records/`，本项留证据指针。
2. **执行器可达性探测（执行者，不训练）**：探测机体取第 1 步绑定的现场机体；若明确改在另一机体上研究，须标为新机体实验，结果不直接归因于原策略。优先核 swing/twist 刚度、阻尼及其他轴代偿，保留原限位基线。正弦信号走原始 action 经 scale/clip 的正式动作通路，不直接下发关节目标（后者绕过 scale，无法检验上述假设）；可另以直接目标作执行器对照，但单独标注。刚度（连同阻尼）、scale、力矩上限三类变体分别比较，探测前写明组合与幅度。读数：目标与实际关节角的幅值比、相位、跟踪误差，零动作站立高度和腹部接触，悬空（固定根）与着地分别测。力矩须写明信号来源与采样频率：当前隐式 PD 的 `computed_effort`/`applied_effort` 为近似值（`E:/IsaacLab/source/isaaclab/isaaclab/actuators/actuator_pd.py:124`），只有估计通道时记为“估计饱和”，须结合跟踪误差判断，不能单独确认权限不足。第 1 步策略 rollout 的饱和统计同此口径。结果归验收记录，本项留指针。
3. **定义测量（执行者）**：明确小腿有向长轴、地面法线、支撑接触对象、落地事件及前后阶段，避免用膝角或未经核定的刚体局部轴替代骨段倾角。区分目标动作和实际响应、首次触地与持续支撑、正常推进倾斜与过度折叠；现有足端高度代理不作为正式落地事件。落地倾角按前后向与横向分量分别定口径，不用单一阈值。几何可达性沿用第 1 步核查。接触测量复用 `work/active/lizard2-contact-protocol.md`，有缺口交其处理。
4. **按探测结论分支（执行者）**：
   - 两项改动均获支持（大腿驱动不足，且降低小腿不破坏支撑）：经用户选定载体与幅度后按版本纪律开新版本，组合与单项对照训练。
   - 只支持一项：仅测试该改动，另一项保留原执行器配置。
   - 假设不成立（大腿跟踪正常，或降低小腿损害支撑）：保留执行器配置，直接转入策略目标与落地姿态对照。
   - 几何核查显示目标落地姿态不可达或须多轴联动：不直接添加奖励；先报告用户，在动作空间、轴配合或机体换代中选定，换机体按资产换代流程，不由执行者自行决定。

   策略目标排查可先于改参进行：核对该策略实际启用的速度跟随、动作变化、力矩、关节软限位、腾空及接触相关奖励，追踪 raw action、processed target、last_action 的实际口径；检查固定大腿/小腿代偿是否仍能获取目标收益。结合训练阶段复读，不凭输出偏置认定某奖励项造成正向推力，不以 clamp 的局部导数解释 PPO 无法恢复。需要策略目标对照时，优先考虑后腿落地窗口内、有容差的小腿朝向约束，再决定前腿是否需要独立口径。比较前确定阈值、窗口、权重、对照条件及停止线，不把整个支撑期锁成竖直。检查无效摆腿、少落地、拖地不抬腿、接触抖动和牺牲速度来规避目标的可能。
5. **验证与交接（后续实施）**：方案确定后按版本纪律接入，验证测量与奖励的正反例和回归修复前失败、修复后通过。行为对照同时观察落地倾角分布、髋膝运动及协调、有效推进、滑移、接触与落地次数、稳定性和命令跟随；报告项与通过门槛分开。若开展训练，执行 `ablation_harness/HARNESS.md` 的训后固定流程，默认 robust，录制并实际验看九宫格，保留原片与 `matrix.json`，不以总奖励代替步态证据。
6. **审核（执行者交接）**：实际实现与行为证据齐备后置 pending_review，交不带执笔历史的新上下文按关闭条件审核；本次诊断回填不代表修复或验收完成。
