## 目标与边界

将 baseline / Lizard2 的常规 eval 做成：**采集条件与字段确定 → 仿真采集并保存 → 离线计算指标 →
按协议判定 → 异常时专项归因**。一次命令仍可完成全流程，各阶段能单独执行和失败后重试。
默认采齐常规验收需要的基础量；不按本次启用的门槛裁剪字段。历史测量依据见 `evidence`，本计划不复制读数。

实施范围为 `baseline_eval.py`、`baseline_frames.py`、`baseline_metrics.py` 及其既有契约测试。
常规步态测量与 Lizard2 新协议属于本项；训练配方、奖励、资产、重训、rough `eval.py` 迁移不属于本项。
详细地面归因继续由 `floor-contact-attribution` 承担，开训协议闸门归 `eval-protocol-before-training`。

## 当前实现入口

- `baseline_frames.COLUMNS` / `BaselineFrames.add`：现有字段整套采集，有形状和轴标契约。
- `baseline_eval.run`：采集后先调用 `judge` 再保存帧；命令使用环境重采样；部分物理量在采集时被压缩。
- `baseline_metrics.judge` / `main`：可以脱离仿真复判；判据有列依赖，`report_only` 尚无完整的实现覆盖检查。
- `baseline_frames.FORMAT` 与 `judge_semantics.json`：分别承担数据格式、判据语义身份；新工作沿用这些边界。

## 数据与职责设计

### 采集条件、数据、判据分开表达

采集条件声明任务与配方身份、检查点、策略模式、seed、场景、命令序列、窗口、采样周期和字段版本；
判据声明指标、公式身份、阈值、聚合与通过条件。数据记录保留实际执行的条件、字段单位/坐标系/轴标、
初态、终止时刻、采集状态和来源。复判报告同时指向原始记录摘要、实际采集条件与本次判据摘要。

优先在现有协议与记录中建立独立块，避免引入通用注册平台。旧协议通过显式兼容路径读取；离线复判时，
只能更换判据声明，不能覆盖原始采集身份。条件不兼容、必需字段缺失或采样能力不足，必须说明为何不能判。

### 默认采集的范围

| 数据 | 用途与约束 | 落点 |
|---|---|---|
| 基座位置、完整姿态、线/角速度；实际命令及其生效帧；终止/超时 | 跟踪、位移、姿态、命令阶跃和有效区间可复算；明确 step 前命令与 step 后状态的配对 | `baseline_frames` 契约、`baseline_eval` 采集 |
| 逐 body 接触合力向量、逐 env 质量/重力来源、body/foot 名称 | 离线计算承重、接触与占空比；不只留下布尔接触和跨 body 求和结果；合力不宣称为地面专属力 | 同上 |
| 足端姿态、线/角速度、足底几何参考、地面高度/法向来源 | 离线算离地高度与足底参考点切向速度；参考点、坐标系和几何来源随记录保存 | 同上；几何定义取自实际资产 |
| 现有非足网格诊断所需量 | 保留现有能力，记录使用的部位、资产和测量身份；不得靠旧家族固定网格路径解释新资产 | `baseline_eval` 几何适配 |

只采验收所需的 body 状态，不无条件保存整个引擎状态。兼容旧判据所需的派生列可保留，但新指标优先由基础量
在离线侧计算。常规记录的尺寸、采集耗时、峰值内存必须实测后入验收记录；先优化批量传输，不先丢字段。
不预设 GPU 全窗缓存或磁盘分块方案，以实测瓶颈决定。

专项采集：地面/自碰撞分离的接触对、接触点力与摩擦归因、关节力矩专题、录像。按异常需要单独开，
所用传感器和环境覆盖必须记入条件；不得静默改冻结配方。协议里的未实现报告项须补实现或在新协议中明确移除。

## 实施顺序与阶段验收

### P0：采集结果先保存，判分失败可恢复

落点：`baseline_eval.run/main`、`baseline_frames.save/load`、现有 `test_baseline_contract.py`。

- 完成采集契约检查后，先保存含完整来源与条件的记录，再调用离线判分；记录临时写入后原子完成，拒绝覆盖已有采集。
- 全流程入口默认采集后判分，提供仅采集路径；复判沿用现有离线入口。判分异常单独报告，不改写已完成的帧文件。
- 数据无效、策略不达标、工具执行错误分别表达；未完整采集的窗口不得具有“采集完成”状态。
- 不承诺从进程被杀的任意一帧续采；完整采集落盘后的判分失败必须可恢复。检查 Kit 关停是否吞掉错误退出状态。

验收：注入判分异常后仍能加载同一份完整记录，修复后无需启动仿真即可复判；写盘失败不留下可当成完整结果的
目标文件；重试不覆盖证据；CPU/GPU 来源元数据均可在 CPU 上读取。回归先证明撤掉修复会失败，再恢复验证。

### P1：扩展并版本化常规采集契约

落点：`baseline_frames`、`baseline_eval.snapshot`、几何辅助函数与既有帧契约测试。

- 新增数据格式版本与明确读侧分派；旧格式继续可读，不就地改旧字段含义，不伪造旧记录缺失量。
- 按上表采基础量，帧字段与 meta 均转换为独立的 CPU 数据；保存单位、坐标系、部位轴标、采样频率与几何引用。
- 终止帧在物理步后/复位前采集，重生帧排除；命令记录对应驱动该物理步的命令，避免重采样边界右移。
- 采集身份保存资产、配置、执行代码与测量实现来源；同一记录脱离当前工作树仍可解释，不能读取当前资产补历史几何。
- 常规采样频率能否支撑短接触和滑移测量，用子步参照验证；若会漏事件，显式增加所需采样/聚合并记录其语义。

验收：轴顺序置换、漏字段、非有限值、命令阶跃、真实早终止均有可观察结果；缺新字段的旧数据在新步态判据下
明确不可判；默认字段不随启用门槛变化；测得常规采集开销。真实早终止取证与 `baseline-eval-measurement-trust` 共用。

### P2：离线指标、判据与报告各有可检查的输入输出

落点：`baseline_metrics` 内部计算与判定函数、`CRITERION_KINDS`、报告项依赖、`judge_semantics.json`。

- 指标计算只读记录与显式测量参数，返回值及有效样本数；判据读取这些结果做门槛判断。共用一个计算结果，防止报告值
  和判据值各算一遍而漂移；不为形式分层强制拆新模块。每个指标声明列依赖、单位与适用条件。
- 增加足底离地高度和承重阶段切向运动指标。刚体速度按参考点计算，包含 `v + ω × r`；明确是足底参考点近似还是
  实际接触点。未经接触参照验证的近似不能标成真实接触滑移、也不能直接升级正式滑移门槛。
- 建立所声明报告项的完整性检查：未知名称/没有实现拒绝；缺数据或无有效样本显式报不可用及原因。必需判据缺证据
  则 `invalid`，可选诊断缺数据不能静默消失，也不自动改写策略判决。
- 报告分列测量有效性、任务表现、行为有效性；采集完成与否、判分成功与否、策略是否达标分别可读。

验收：用合成轨迹核对静止、纯平移、纯转动、摆动后落地、持续滑行、失败后复位；至少包含“旧门槛通过但步态异常”
和正常对照。声明不存在的报告项必须被拒；已实现的 `foot_duty` 等先核实映射，不能照旧记录的缺项清单重复实现。
旧 judge 的冻结行为保留；公式/聚合/失败帧语义变化使用新 kind 与 reader，阈值变化归新协议。

### P3：固定评测场景与新协议

落点：`baseline_eval` 命令驱动、新协议文件、现有命令播放/契约测试。

- 复用既有命令播放能力前先核对坐标系和注入时序；按 env 分配固定场景，每个速度带都有计划样本，并包含启动、停止
  与带间切换。明确命令重采样由谁驱动，避免环境内部再次改命令或策略观察到上一帧命令。
- 将命令序列、场景分配、稳态等待窗与覆盖要求写入采集条件；每带分别报告分配数、实际执行数和存活有效样本数。
  分清未安排/未执行造成的覆盖缺口与策略提前失败造成的证据损失，保留存活失败，不能把失败策略都归为采集错误。
- 创建新协议承接新条件和步态判据，旧协议与旧报告保留原义。固定命令条件下重跑后才能形成新结果，不用旧随机采样
  记录冒充新场景。同表比较须核对采集条件、字段/测量版本和判据身份。

验收：固定 seed 和场景映射可复现实际命令；有效配置必覆盖所声明场景，环境数不足明确拒绝；命令阶跃与策略输入
对齐；没有样本的带不能通过；纯阈值复判不改帧摘要；改变场景、采样要求或缺失量必须重新采集。

### P4：运行时闭环与发布

- 在同一既有检查点上跑新采集；分别做一次默认全流程与同帧离线复判，核对指标/判据一致及记录摘要未改变。
- 正常与异常对照验证步态测量，专项接触验证引用 `floor-contact-attribution` 的证据；产品阈值未定时只交付诊断，
  不声明新步态验收通过，也不据此关闭本项。真实早终止证据未取得时如实保留对应事项。
- 运行相关回归与 `run_offline_checks.bat`；新增检查优先放入既有入口。故障回归按仓规验证“无修复失败、有修复通过”。
- 更新 `HARNESS.md` 的已成立契约与命令，按其版本纪律发布 harness 与新协议身份；既有锚点缺项归
  `harness-version-anchor-missing` 协调处理，不能把本轮实现倒填为旧版本内容。
- 实测、性能和结论只写 `acceptance/records/`；本项及 Lizard2 家族事项只留落点和证据指针。

## 冻结前的决定与风险

| 事项 | 决定来源 / 验证方式 | 阻挡范围 |
|---|---|---|
| 抬脚高度、所需摆动脚数、滑移容限 | 所有者产品口径 + 独立正常/异常样本；历史异常仅作反例，不直接给允许阈值 | 相应新判据冻结，不阻挡 P0/P1 |
| 足底参考点是否足以测滑移 | 静止/旋转反例 + 地面接触参照；不成立时标近似并转专项测量 | 正式滑移结论 |
| 持续非足承重阈值的标定缺口 | 沿既有家族事项补样本，引用证据 | 对应判据的可信性声明 |
| 已冻结协议数值的就地修改保护 | `freeze-maintenance-simplification` 已有待决机制；本项只消费其决定 | 声称“协议数值已由机器锁住”；报告摘要不等于批准锚 |
| 平地、静态地面和接触合力假设 | 条件与指标适用域显式检查；换地形/启用自碰撞须重新验证 | 超出当前平地范围的复用 |

最大的长期风险是“字段越来越多，却仍没有可复算的语义与采集条件”。阶段验收必须同时证明字段来源、时间对齐、
坐标系和适用域；完整记录不等于结论可信。另一个风险是两份入口各维护一套指标：新增逻辑只落一处，入口负责编排。

## 未覆盖边界

不建设通用采集插件、表达式判据语言或全任务框架；不保存全部引擎状态；不承诺旧帧可计算当时未采集的物理量。
P0–P4 的实施不会自动完成训练启动闸门、资产/接触参数决策或原有专项归因事项；这些事项的关闭仍按各自条件取证。
