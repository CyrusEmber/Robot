# 项目分批精简总纲

先减少重复实现、闲置入口和读写依赖，再处理大文件。每批从可复验的问题起步，优先复用现有实现、测试和目录。只有依赖边界与维护成本都改善时才提取共享逻辑。收益看实际删掉的执行代码、入口和字节，文件搬移单独记录。

机体迭代期间，持续保存与机体版本绑定的验收文档。原始诊断产物按当前用途暂留，失败现场和未核定材料由事项承接。旧版本有明确结论、原始数据已无在办用途时，复核后处置。稳定机体明确冻结并确定正式验收目的后，再决定原始产物的保存范围。[诊断产物规则](diagnostic_artifacts.md#版本文档与原始产物)

## 第一批 诊断入口与临时产物

1. 用仓库配置解释器和已有局部路径源报告复现回放命令缺陷。修复 `local_path_view.py` 的解释器记录，与 `local_path_check.py` 统一用 `sys.executable`。
2. 顺手删掉重复命令构造及通用工具转接，沿用现有路径、登记和摘要实现。移出的执行逻辑随改动进入实际报告及运行记录的绑定。
3. 复用既有四模式和历史报告回放，逐字段核对判词、采样和读数，逐项核对解释器、源码和产物摘要的预期变化。同名拒写与写后故障留存沿用现有回归。
4. 从具名旧产物开始，核查机体版本、写者、真实消费者和对应验收文档。仍有用途的材料先接通并实测读取，核定退役的材料记录文档落点和处置范围。实测清理前后的文件数和字节数。[具体样本与验收步骤](../../work/active/diagnostic-artifact-lifecycle.md)

## 第二批 验证工具与测试

1. 按现有离线套件条目查各自保护的行为、测试样本和初始化开销，从重复覆盖或明确退役的契约入手。
2. 复用已有样本、检查和调度，合并重合断言。确认等价覆盖或契约退役后，删除多余入口。[离线检查规范](../tools/verify/OFFLINE_CHECKS.md)
3. 用既有真实反例验证保留的检查仍会拒绝，再跑离线套件并记录同条件下的执行成本。

## 第三批 训练核心与旧线解耦

1. 核清 `curriculum_state.py` 对 `teacher_mdp.py` 的 SIR 与读数依赖，查现役和历史续训入口、冻结配方及测试的实际使用。
2. 沿现有事项选定切分边界，保住在用符号和兼容入口。确认依赖闭合后退役旧奖励和终止代码。[旧训练实现清理事项](../../work/active/teacher-mdp-residual-kernels.md)
3. 验证任务注册、配置构建、观测顺序、旧 checkpoint 续训和缺状态拒绝。涉及已冻结训练语义时按版本纪律处理。

## 第四批 评测与运行记录

1. 沿 `eval.py`、`record.py` 和 `runrecord` 的实际调用梳理重复摘要、路径解析和绑定检查。
2. 合并语义等价的实现，按训练与评测各自的身份、版本和读取契约验证接线。[退出码事项](../../work/active/exit-status-swallowed-by-app-close.md)
3. 用同一输入比较冻结协议输出，复读旧记录，再用真实子进程核验成功和失败的退出码。训后评估和录像沿用 [HARNESS.md](../../ablation_harness/HARNESS.md#训后评估固定流程)。

## 第五批 大资产与历史产物

1. 按跟踪文件的字节数找大项，查 Blender 源件、历史候选、checkpoint 和评测帧的消费者、冻结资产锁与恢复约定。
2. 按历史版本契约与当前使用情况处置。仍需保留的资产先测恢复、哈希和相对网格引用，核定可退役的文件逐项记理由和影响。
3. 从隔离位置验证现役消费和保留的历史入口，分别记录当前检出体积、本机占用的实际变化与 Git 历史占用。

## 每步怎么记录

总纲保存实施顺序与验收条件，已有事项记录下一动作。每步实际修改的文件和实现差异由 Git 记录。验收记录保存改动落点、改前改后对照、处置结果和未覆盖范围，其它文档引用对应记录。
