# baseline/v2 方案（全量式，同线第二版）

> 上游母本 = `baseline/v1`（`base.json` 指向 v1 的冻结 golden）。结果见 [NOTES.md](NOTES.md)；
> 线路线见 [../PLAN.md](../PLAN.md)。本版只加**两个变量**，其余一切照 v1 冻结值不动。
> 修订：v2.1（2026-09-21，动作权限的做法定为"去权限保留 PD"，见 §修订）

## 目的与假设

v1 回答了"平地、固定 0.5 m/s 能否学会持续行走"，结论是**没学会**——策略用脖子蹭地承重（`neck_pitch`
82–90 N = 体重的 11.6–12.8%；`neck_frac` 0.476 是"满足 >10% 判据的时间占比"，不是载荷比）、后脚
duty 0.002，靠"拖颈蹭行"过掉了当时只有速度与存活的口径
（证据见 `acceptance/records/2026-09-20-baseline-flat-eval-protocol.md`）。

v2 问三个正交的问题，**一次只加三个变量**：

1. **速度窗口**：把命令从定点 `0.5` 打开到 `1.0–3.0 m/s`（框架自身 10 s 重采样 ⇒ 20 s 回合含两次
   命令与一次换速），测的是**速度区间内**的行走，而不是一个点的行走。
2. **脚板权限**：把 `.*_foot_joint` 从动作组里移除（动作 26 → 22 维），脚板保留 PD 与执行器组，
   但不再受策略驱动 —— 断掉"靠脚掌蠕动充数"这条捷径，迫使髋/膝承担推进。
3. **头链触地终止**：胸/颈的**竖直**接触反力 > **1 N**（与 `base_contact` 同一个"接触"阈值）即终止回合，
   `dwell_s: 0` —— 平地不给头留可以踩的东西，碰了就结束。v1 的失败正是"脖子压地承重"而当时零代价，
   这条把它变成训练期就付不起的动作。先前一版写的是 **10% 体重持续 0.5 s**（v10 `DIAGNOSE.md` 的读数
   口径）：那是**承重**判据，会被接触抖动击穿 —— 该策略 66% 的帧压在 10% 体重之上（时均 87.2 N =
   12.3% 体重），却**从未连续超过 0.22 s**，照旧定义会整段穿过这条闸门。

假设：若 v1 的失败主要来自"捷径不被计价"而非"机器人做不到"，那么堵住捷径（2、3）+ 打开速度窗口后，
失败应表现为**够不到 3 m/s**或**姿态/承重再次越界**，而不是"完全不动"。

## 相对上版的 diff（逐项）

| 项 | v1 | v2 | 依据 |
|---|---|---|---|
| 命令 | 定点 `[0.5, 0.5]` 各轴 | `lin_vel_x [1.0, 3.0]`；`lin_vel_y`/`ang_vel_z` 仍 0 | 只加速度这一个变量；侧向/转向留着以防归因混淆 |
| 重采样 | 无关（定点） | 框架默认 10 s，不覆盖 | 与 v14 同口径，换速也在考核内 |
| 动作组 | `legs` 4 组模式（含 `.*_foot_joint`），26 维 | `legs` 3 组模式（去 `foot_joint`），22 维 | 断捷径；动作组内容随参数进 yaml（`action.joints`） |
| `feet` 执行器组 | 200/12/70/6 | **不变** | 去的是动作权限，不是关节：脚仍被 PD 拉向默认姿态 |
| 终止 | `base_contact`（`base_link` > 1 N） | 增加 **`head_load_contact`**：`chest_.*`/`neck_.*` 竖直反力 > **1 N**（同一"接触"值）即终止，dwell 0 | 把 v1 的失败姿态变成终止；`ContactLoadDwellTerm` 本线自持（照 `teacher_mdp.RollOverTerm` 的 reset 约定），dwell 能力保留、本版取 0 |
| 配方元素列表 | 十项 | **逐项相同**（终止那条也走既有 element，由 yaml 开关） | 参数进配置：v1 的 yaml 无 `contact_load_guard` ⇒ 解析结果不变（golden 已证） |
| 地形 / 观测 / 网络 / 奖励 / 终止 / DR / 课程 | 见 v1 | **逐项不变** | 本版不加别的变量 |

`params_version` 从 `v1` 变为 `v2`；配方元素列表与 v1 **完全相同**（差异全在 yaml），
所以两个版本的差别可以在一份 yaml 里读完，而不是靠人眼 diff 两条代码路径。

## 验收（**开训前必须冻结**）

**硬前置**：本版不接受"先训再想怎么判"。开训前必须完成——

1. 冻结本版的验收协议（协议族下一版：命令由定点改区间，逐帧记录**实际下发**命令；两条门槛改相对口径，
   见下），并由启动闸门保证"协议不存在或摘要不符 ⇒ 拒绝开训"（在办事项 `work/active/eval-protocol-before-training.md`）。
2. 开训前探针按新接口复测：命令落在 `[1.0, 3.0]` 且逐 env 采样、动作维度 22、脚关节无动作权、
   姿态/承重/网格四条与 v1 同尺子（`work/active/baseline-eval-protocol-gap.md`）。

门槛（除标注外沿用 v1 的仓库先例值）：

| 轴 | 口径 | 阈值 | 来源 |
|---|---|---|---|
| 跟踪 | 逐帧 `|v_fwd − v_cmd|`，按 `v_cmd` 归一后取均值 | < 0.2（**本版新定**，1–3 m/s 下绝对 MAE 无先例） | 需开训前确认 |
| 位移 | `实际位移 / Σ(v_cmd·dt)` | > 0.8（**本版新定**，定点 8 m 在区间下无意义） | 需开训前确认 |
| 存活 | `time_out` 占比 | > 0.9 | v1 |
| 姿态 | tilt ≤ 40° 持续 0.5 s | 几何 fall（`metrics.fall_flags`） | 仓库先例 |
| 触地 | 非足 body 竖直反力（逐帧） | **待拍板**：建议与训练终止**同一判据**（任一帧 > 1 N 即红）；现行 v2 协议仍是"≥ 10% 体重持续 0.5 s" | 训练终止 + `base_contact` 的 1 N；现行值来自 v10 DIAGNOSE.md |
| 入地 | 非足碰撞网格最低世界 z（**顶点**法） | 诊断（不给门槛） | `≥ −0.01` 是 2026-09-21 按"实测稳态穿插 5 mm"校准出来的**观测值**，不得当允许阈值；随机策略实测入地 7.7 mm 仍会过 ⇒ 已降为诊断项 |

**训练侧与验收侧的同一把尺子**：第 3 个变量（终止）现在是**接触**判据（竖向 > 1 N 即终止）。
验收侧的对应判据**尚未冻结**：现行 v2 协议仍写"≥ 10% 体重持续 0.5 s"，而它的训练终止已经是"碰了就结束"
—— 计划把验收也改成同一判据（任一帧 > 1 N 即红），但这是协议内容，须在拍板后与命令区间、逐帧命令
一并冻结（在办事项 `work/active/baseline-eval-protocol-gap.md`）。冻结前**不得开训**。

**诊断项（不给门槛）**：脚 duty、脚载荷份额、`feet_down`、侧向速度、yaw 偏移、tilt 最大值、
每 body 网格最低 z —— 步态口径没有先例，故只报告。
