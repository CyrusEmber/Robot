### 承重闭环（2026-09-14 补；`out/v10_loadclosure` = `--phases 0,1`，`out/v10_meshz` = `--phases 0,2`）

要回答的问题：足部合力只到 0.90×m·g，缺的 ~10% 去哪了。原口径**只加四只脚**
（`net_forces_w[:, feet, 2]`），而 `contact_forces` 传感器覆盖 `Robot/.*` **全部 27 个 body**
（`velocity_env_cfg.py:79`）——base/spine/尾巴从未加进账。补丁做三件事：① 逐 body 法向力全部
加总（`load_closure()`）；② 报 `m·a_z` 等效量排除动量项；③ **把碰撞网格 bbox 的 8 个角点按
body 位姿投到世界系取最低 z**（`mesh_min_z()`）——因为 `net_forces_w` 只给"这个 body 受力"，
不给"它在碰谁"，而 body 原点 z 会被网格自身偏置骗。

**同一会话两窗口对照（`out/v10_meshz/p0_measure_check.json`）**

| 量 | 策略零命令 4 s | 零动作 4 s（真静立） |
|---|---|---|
| ΣF_全body / m·g | **1.0044**（残差 −3.1 N） | **1.0017**（残差 1.2 N） |
| `momentum_can_explain` | false（Δv_z −0.011） | false（Δv_z −0.0006） |
| 尾尖 `tail3_pitch` 力 | **72.83 N = 10.3% 体重** | **0 N** |
| 尾尖**碰撞网格最低 z** | **−0.131 m（扎进地面 13 cm）** | **+0.348 m（离地 35 cm）** |
| `tail2_pitch` / `tail1_pitch` 网格最低 z | +0.274 / +0.450 | +0.494 / +0.547 |
| 腹 `base_link` 网格最低 z | +0.419 | +0.513 |
| 头 `neck_pitch` 网格最低 z | +1.044 | +0.913 |
| `tail1_pitch` / `tail2_pitch` 关节角 | **−0.335 / −0.355 rad** | −0.115 / −0.039 rad |

**四只脚**：策略窗口 0.90×m·g（lf 0.645 / rf 0.212 / rr 0.044 / rl 0.000）；零动作窗口
**1.0017×m·g 四脚均分**（0.298/0.278/0.232/0.194，z 全为 0.074 m 贴地）。另 9 个无碰撞网格的
body（4×`_kfe` + 5×`_yaw`）力恒 0——**它们没有碰撞体，力必然为 0，不能当作"未承重"的证据**。

**结论（缺额已闭环）**

1. **缺的 10% 就是尾尖 `tail3_pitch`：策略把尾巴当第五条支撑腿用。** 全 body 加总后账平
   （0.90 四脚 + 0.10 尾尖 ≈ 1.00）。网格证据坐实是**撑地**：尾尖网格最低点 **z = −0.131 m**
   （地面以下），而同一时刻 `tail1/tail2_pitch` 网格还在 +0.45 / +0.27 m、腹在 +0.42 m。
2. **是策略主动做的，不是资产/PD/出生。** 同一权重换控制器：零动作时尾尖 **0 N、离地
   0.35 m**，尾 pitch 关节仅 −0.115/−0.039 rad；策略零命令时把尾**多折约 0.25 rad**、
   压进地面 13 cm 并扛 10%。动作量级（≈−0.34 rad ≈ −19°）不是噪声。
3. **动量项排除。** 真静立窗口 Δv_z = −0.0006 m/s；要凭空造出 10% 缺额需 a_z ≈ −0.97 m/s²
   持续 1.2 s（Δv_z ≈ −1.2 m/s），与"站得住"矛盾。
4. **腹与头颈确实没承重**——`base_link` / `chest_pitch` / `neck_pitch` 力全程 **0.0 N**，网格
   最低点分别 +0.42 / +0.46 / +1.04 m。原"belly≈0、头颈无承重"**方向对但论证方式不合规**：
   那是**阈值**判出来的（`belly_gt10n_frac` = `>10 N`、`neck_support_frac` = `>10% 体重`）。
   阈值只回答"压没压上去"，回答不了"差多少"——**69.6 N 的尾尖在两项目前口径下完全不可见**：
   尾不在 `SPINE_BODIES` 里，且 69.6/706.3 = 9.86% < 10%。
5. **尾巴撑地是"免费"的（新发现的奖励漏洞）。** `names.undesired_contact_body_names` 只有
   `.*_hfe` / `.*_kfe`（`v10/lizard_params.yaml:122-124`），`base_link` 另有专用
   `belly_contact_force`（`teacher_mdp.py:532`）——**尾巴、头颈、`_haa` 触地没有任何项惩罚**。
   与"跟踪核只罚慢、不罚横向/超速"同属一类：**策略能用但不付代价的动作**。
6. **连续性**：10 Hz 下采样后尾尖仍有 9.2%（64.8 N）→ 是持续支撑，不是抽样假象。下采样同窗口
   总力低读 ~3 pp（0.9603 vs 0.9898），**存档 json 里的载荷量整体偏保守**。

要分清侧滑与转弯必须做**时间积分拆分**：分别积 `∫|v_y^body| dt`（侧滑路程）与

**异常 2 —— 超速而账本满分**：`overshoot` 低速 +48…54%、1.0 档 +6…8%；跟踪账本却 1.445–1.496

`clamp(proj, max=speed_c)`，即**超速不扣分（饱和中性）**；且 `proj` 只取命令方向投影，
**横向分量不进分子、同样不受约束**。推论强度限定：这只证明"超速无代价"，是超速的
**必要条件而非充分条件**——不能单凭本项断言最优解"必然"超速（还取决于该 term 权重占比与
其余项是否抑制超速）。可下的结论只有：**账本不能用来判"跟得准不准"**。

**异常 3 —— 前后肢分工失衡 + 随速度提前腾空**：`foot_duty` 前两脚 0.48–0.80（几乎常触地）

### 实现备注（坑与修法，防再踩）

1. `reset_base` 基类默认 yaw ±π 随机——体坐标命令导致各 env 往随机方向走，
   台阶列全部失真；诊断脚本钉 `pose_range["yaw"]=(0,0)`。
2. 单级台阶条件：`platform_width` 必须**严格大于** `size−2*border`；恰好相等
   时 floor 除法给 num_steps=1 = 两级台阶（离线 trimesh 校验抓出）。
3. rsl_rl wrapper 的 `reset()` 返回 `(obs, extras)` 元组，策略吃裸 obs。
4. 接触力/体重需先走若干物理步再读（reset 后首读为 0）。
5. 脚着地要同时存**接触力**（判据）与**脚 body z**（几何复核）：只存 `feet_down`
   整数计数就没法回答"哪只脚悬空"，逐脚 `fz_feet`/`foot_z` 必须落进 json
   （2026-09-11 补，p1c 存档因缺逐脚时序只能重跑）。
6. 脚 body 原点在贴地时有 ~0.07 m 常量偏置——"悬空"要跟同 run 的贴地脚比，
   不能拿绝对 z 比 0。
7. **脚序 = `[rr, rl, rf, lf]`**，命名由出生步 base 系实测钉死：**rr=右后, rl=左后,
   rf=右前, lf=左前**（前对 `<侧><前后>`、后对 `<前后><侧>`）。读载荷数组前先确认顺序
   ——首版把 rl 写成"右后"、把载荷读成"后重前轻"，方向全反。
8. **四元数是 xyzw**（`utils/math.py:453`：`q_x, q_y, q_z, q_w = quat[:, 0..3]`）。
   一切旋转走 lib（`quat_apply` / `quat_apply_inverse` / `yaw_quat` /
   `euler_xyz_from_quat`），**别手写分量**：首版按 wxyz 手写 → yaw 差 177.6°、
   tilt 分支漏掉 roll（那才是"180° 怪现象"的真因，不是资产偏置）。
9. **体重取真实质量 × g**（`data.body_mass.sum()` = 72.0 kg → 706.3 N），不要拿某一
   时刻的足部接触力之和当体重：0.5 s 时读到 856 N（+21%），把所有载荷比例压低了 21%。
   **承重校验必须加全 body**（2026-09-14 定案）：只加四只脚得 0.90×m·g，缺的 10% 是
   **尾尖 `tail3_pitch`**（策略零命令下 69.6–72.8 N）；全 body 加总后 0.986–1.004 全平。
   读数用**同一窗口的逐 body 平均 Fz**，不要用阈值项（`belly_gt10n_frac` / `neck_support_frac`
   是事件判据，9.86% 的尾尖在两项目前口径下都读作 0）。
10. **json 时序是下采样**（5 帧抽 1）："某脚全程 0 力"这类话必须回到全 50 Hz 口径再确认
    （rl 全频率 duty 2%、均值 1.02 N，抽样后成 0/0）。下采样还会让**全 body 总力低读 ~3 个
    百分点**（0.9603 vs 0.9898）——存档 json 里的载荷量整体偏保守，别拿它当秤。
11. **别把仿真的 stdout 接管道过滤器**（`| findstr ...`）：过滤器提前退出会掐断 python
    的 stdout → 进程被杀、只落一半 json（首次 Phase 2 重跑就 5/9 断）。重定向到文件再筛。
12. **残差先剔出生帧再报口径**：出生落地那一帧把全段 max 拉到 0.46（残差本身中位数

    作对照——它可能掩盖间歇性错误。三种口径（全段 / 有效段 / 分位数）都要写明，别只留

13. **阈值判据 ≠ 载荷账**（2026-09-14 定案）：`belly_gt10n_frac`（`>10 N`）、
