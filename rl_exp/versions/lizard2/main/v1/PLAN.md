## 目的与假设

**问题**：把竖直轴从股骨远端（旧构型 `hfe`）搬到腿根（新构型的 `hip`）之后，同一套 v1 配方
（平地、无课程、无 DR、7 项奖励、躯干/头颈接触终止）能不能在 **0–2 m/s 的区间命令**下学会持续行走？

**为什么问这个**：旧构型下"名义迈步轴装在错的那一段"是实测结论（`hfe` 力臂 0.06–0.07 m ⇒ 扫满行程
也只有 0.11–0.13 m 脚掌位移；见 `acceptance/records/2026-09-21-lizard-leg-axis-kinematics.md`）。
新构型把这条轴放到腿根，力臂 0.49 m、承重姿态下四腿前后行程 0.546–0.558 m
（`acceptance/records/2026-09-22-lizard2-stride-at-load.md`）。**几何证据已成立，训练要回答的是它够不够学**。

**假设（可证伪）**：若旧构型"竖着走不动"主要来自迈步轴的力臂而非奖励/课程/网络，则在新骨骼上跑
同一配方，失败形态应当是**够不到区间上界**（2 m/s）或**姿态/承重越界**，而不是**完全不动或原地扭**。

**归因边界（先说清）**：本版与旧线 baseline v1 之间同时变了两件事 —— 骨骼与命令窗口（定点 0.5 → 区间
0–2）。因此本版结果**只能**回答"新构型 + 本配方能否走"，**不能**单独归因于骨骼修正；要把两者分开需要
后者单开一版（见「风险与挂账」第 1 条）。

**判据的可执行口径**（固定窗口、失败后如何处理）见「验收」，不以形容词代替。

## 验收

**硬前置（开训前必须完成，否则不得开训）**：

1. **冻结本线的评测协议**：命令区间 + 逐帧记录**实际下发**命令 + 下表的判据种类与参数，
   并由启动闸门保证"协议不存在或摘要不符 ⇒ 拒绝开训"。现行 `baseline_flat_*.json` 是旧线的协议，
   **不能直接借用**（命令窗口不同；且它用 `clamp_min(1e-6)` 的旧归一，在含零窗口上不稳定）。
   冻结时同时要：新增 `tracking_banded_v1` / `displacement_banded_v1` 两个种类（各带反例测试，
   仓库规则：非平凡逻辑要留一条能挂掉的检查）、给新种类一个自己的 judge id
   （`baseline_metrics.JUDGE_ID` 随判决走）、把 `non_foot_carrier_v1` 的 `fraction`/`sustain_s` 定死。
2. **启动探针按本版接口复测**：命令落在 `[0.0, 2.0]` 且逐 env 采样、`lin_vel_y`/`ang_vel_z` 恒 0、
   `heading_command`/`rel_standing_envs` 未改写下发值、动作维数 30 且**每个关节恰被一个动作项覆盖**、
   观测 102 维（组名/宽度/有限性）。`baseline_probe.py` 现硬编码 `(0.5,0,0)` 与 90 维，需按本版改造后复测
   （放宽断言不算复测）。
3. **落地姿态目视**：本版是 plane，目视只需确认零动作站姿与脚掌接触正常（碎石/地形那两条不适用）。
4. **执行器能力曲线（决定 0–2 窗口是否物理可达）**，分两层测，两层都要记读数：
   - **层一（悬空跟踪）**：机器人吊起/无承重，给髋正弦指令 0.5/1.0/1.5/2.0 Hz（幅度 ±0.6 rad），记跟踪误差、
     超调、稳定时间、限幅（饱和）占比、时间步敏感性。**层一失败只说明"这条轨迹难跟踪"，不能证明所有步态都到不了 2 m/s。**
   - **层二（承重协调运动）**：整机在承重姿态下按"接近步态"的协调轨迹走一遍，记实际速度、足端滑移、力矩与角速度峰值。
   - **上限口径必须先测**：本 fork 的 `ImplicitActuatorCfg` 在未设 `velocity_limit_sim` 时**明确丢弃** `velocity_limit`
     （`isaaclab/actuators/actuator_pd.py:80-91` 把 `cfg.velocity_limit` 置 None 并只发 warning），而本线仍在传它
     （`rl_exp/tasks/lizard2_recipe.py:129`）⇒ **`velocity_limit` 不构成仿真里的分母**；`effort_limit` 则被转成
     `effort_limit_sim` 生效（同文件 60-67）。实测前不许引用任何速度预算百分比。
   - 读数里的 `computed_effort` / `applied_effort` 是**近似力矩**（本 fork 隐式执行器的输出），报告必须标注，
     不得称"求解器实测驱动力矩"。
5. **自碰撞检查**：本线 `enabled_self_collisions=False`（`lizard2_recipe.py:149`，与旧线同），所以**不能指望训练
   自己惩罚穿腿/穿身**，而新髋让"腿绕身体横摆"第一次可达。检查必须用**交叠或有符号穿透**（普通距离非负，测不出交叠），
   并区分"相邻关节处的允许重叠"；粗网格扫描**只能找反例、不能证明整个可达集无碰撞**，因此还要覆盖实际动作轨迹
   （探针/评测跑出来的关节序列）。是否把自碰撞打开，是冻结时要明确记录的设计决定。

**固定窗口**：每个 env 固定评测 20 s 的**首回合**；**失败后不得重建 env 续算位移**，**不得只截取失败前的帧**；
确定性策略（`-Play`）与训练采样策略**分开报告**；无 checkpoint 的零动作运行标 `smoke_only`，不算通过。
（口径与旧线 baseline v1 一致，见 `ablation_harness/baseline_eval.py` 的协议族；本线的协议文件待冻结。）

**主轴（下列各条同时成立才算通过）——判据点名 `CRITERION_KINDS` 的种类 + 参数，不写散文**（v4 协议族的理由：
散文让"门槛 key"在不同版本间含义漂移，而种类自带比较、单位与聚合顺序）。**其中四条现有种类不够用，
冻结时必须新增，不许改既有种类的语义**（改了会同时改旧线判据；v4 的 `why_v4` 已把"新观察需要新种类 +
新 judge id"写成规则）：

| 轴 | 种类 + 参数 | 现成？ | 聚合与失败后帧 |
|---|---|---|---|
| 姿态 | `sustained_tilt_v1 {threshold_cos 0.766, sustain_s 0.5}` | ✅ | 逐 env：`alive` 期内出现 `cos(tilt) < 0.766`（即 tilt > 40°）**连续 ≥ 0.5 s** 即跌倒；**任一 env 跌倒即不通过**（`any`，不是比例）。这是"不得出现"的判据，不是"至少稳住 0.5 s" |
| 存活 | `survival_v1 {threshold 0.9}` | ✅ | 未终止 env 占比 > 0.9；失败后帧的速度/位移按最差计入（见下两行） |

| 非足承重（单部位） | `non_foot_carrier_v1 {fraction, sustain_s}` | ✅ | 逐帧逐 body 比阈值、**body 维先 `any`** 再判持续（`_gate_non_foot_carrier_v1`）⇒ 管"某一个部位独自承重"。`fraction` 是**破线水平**：调高更宽松 |
| 非足承重（总量） | `non_foot_load_sum_v1 {fraction_sum, sustain_s}` | ❌ **新增** | 逐帧把**全部非足 body 的竖直向上载荷求和**再比阈值、再判持续 ⇒ 补上"两个部位各 8%、合计 16%"绕过单部位门槛的漏洞 |
| 步态摆动 | `gait_swing_v1 {min_swing_feet, min_air_time_s, min_lift_m, band_mps}` | ❌ **新增** | 只在 `v_cmd ≥ band_mps` 的帧与完整窗口上判（零命令下四脚着地属正常）；每条摆动脚同时满足离地高度、持续离地、**落地后恢复承重**，并报告支撑期足端滑移。`min_swing_feet` 是**产品验收要求，由所有者冻结**；只看 `feet_air_time` 会被接触抖动骗过，所以要多指标合取 |

**旧实现的三处不适用（冻结时必须一起解决，不能照抄 `baseline_flat_*.json`）**：

1. `tracking_v1.normalized` 的分母是 `command.clamp_min(1e-6)`（`ablation_harness/baseline_metrics.py`）：
   在含零窗口上把误差放大成噪声；`displacement_v1.normalized` 是逐 env 先除后平均，`expected_m` 接近 0 时
   比值不稳定。上表的 `floor_mps` 与"先和后除"就是替换它。
2. 分带报告是**判据的一部分**，不是补充项：总均值会掩盖"低速段不走 / 高速段跟不上"这类分段失败。
3. 零命令段必须**写在判据里**（绝对口径），不能靠"反正命令很少"忽略掉。

**非足承重：两条判据、两个都作通过条件（评审 #2 方向修正）**

- `non_foot_carrier_v1`（现成）管**单部位**：逐帧逐 body 比 `fraction`、body 维先 `any` 再判 `sustain_s`。
- `non_foot_load_sum_v1`（新增）管**总量**：逐帧把全部非足 body 的竖直向上载荷**求和**再比 `fraction_sum`、再判持续。
  没有它，"两个部位各 8%、合计 16%"会无声通过。
- **方向**：`fraction`/`fraction_sum` 都是**破线水平**，**调高更宽松**（"抬 fraction 更严"是反话，不作数）。
- **标定**：两个阈值**不得贴着历史故障值选**（旧线 v1 的失败量级 11.6–12.8% 体重）。冻结时用**正常样本 + 已知异常样本 + 噪声**
  标定——健康站立（应远低于阈值）与"脖子压地"复现（应显著高于阈值）——并把标定样本/读数记进记录。
- 载荷聚合（逐 body 竖直反力的和）与接触归属（"非足" = 除 `*_foot` 外全部 link）冻结时写死；后者按本线资产说，换家族要重述。

**补充报告项（明确不作通过门槛）**：侧向速度绝对值、相对初始朝向的 yaw 偏移、逐步 foot duty / 脚载荷份额、
非足 body 的**瞬时**接触与载荷（`limit_n` 口径）、接触期**脚偏航与滑移**（本构型髋摆腿会连脚板朝向一起摆，
是新轴的固有副作用，至少要有读数）、每 body 网格最低 z（`mesh_clearance_v1` 只有在有实测校准值时才可用；
入地读数不得当允许阈值）、动作均值/差分/限位占比。

**跟踪阈值 0.25 的性质（所有者 2026-09-22 的决定）**：作为**本版预注册的工程阈值**接受；**它不是从旧版 0.2
推导出来的**（窗口不同、归一不同），依据只是"区间下界含零、按 0.5 归一后允许更松"。因此配套要求：
**固定评测命令覆盖**（逐 env 固定基命令序列 + 逐帧记录实际下发值）并**分低速/高速报告**，避免总均值掩盖分段失败。

**低速带 ≠ 旧线的定点 0.5（评审 #4）**：本版低带是 `[0.1, 0.5)`、命令随 10 s 重采样变化，**与旧线"定点 0.5"不可比**。
要拿到可比切片，必须另跑一个**同初态、定点 0.5、同窗口、同评测模式**的测试；即便如此，两个方案的**训练命令分布不同**，
结论仍只到"两个训练方案在同一测试上的表现差异"——**不能**由此恢复"骨骼是唯一变量"的归因。

## 风险与挂账（预注册）

1. **上界可能物理不可达（量级估算，必须由硬前置 4 实测）**：髋摆动的远端质量 6.48 kg（haa 2.90 + hfe 1.68 +
   kfe 0.37 + foot 1.53），力臂取实测 0.492 m ⇒ 摆动惯量 ≈ `m r²` ≈ 1.57 kg·m²。按 `τ = I·A·(2πf)²`、
   有效力矩上限 180 N·m（`effort_limit` 转 `effort_limit_sim` 生效）、幅度 ±0.6 rad 反推：
   **2 m/s 对应 f ≈ 1.82 Hz、τ ≈ 123 N·m（占 68%）、峰值角速度 ≈ 6.9 rad/s；f = 2 Hz 时约 83%。**
   三条限定必须先说：① 该惯量模型把质量放在同一半径上，**既可能高估也可能低估**，不是保守下界；
   ② 速度分母尚未成立（`velocity_limit` 被本 fork 丢弃，见硬前置 4）⇒ **不许**引用"占速度预算百分之几"；
   ③ 估算没有 PD 跟踪误差、抬脚/落脚相、滑移与机体俯仰。**结论：上界贴着预算，不是安全区。**
2. **变量不隔离**：本版相对旧线 baseline v1 同时改了骨骼与命令窗口。"骨骼不行"与"区间命令太难"无法区分；
   分带报告给出的低速切片**不是**单变量对照（低带是 `[0.1,0.5)` 且命令在变，见「低速带 ≠ 旧线的定点 0.5」）。
   **本版结论只到"新构型 + 本配方"。**
3. **判废线（开训前写死，事后不改）**：
   - 若表现为**几乎不动**（`|v_fwd|` 时均 < 0.2 m/s 且位移比 < 0.3）或**存活 < 0.5**，
     判"骨骼 + 配方组合不成立"，**先复测资产与几何（行程/力臂/接触归属）再谈调参**，不得先改奖励权重。
   - 若 `non_foot_carrier_v1` 或 `non_foot_load_sum_v1` 破线（非足部位**持续**承重 / 非足载荷总量超标），
     判"没学会走"——两条都**是通过条件**，不给最终 pass、也不折进"过口径但有瑕疵"；下一版要改的是机制
     （终止/奖励/动作权限），不是重读读数。
   - 若训练期命令实际下发值被改写（硬前置 2 未过），该 run 作废——这不是调参问题。
   - 若硬前置 4 的层二证明承重下到不了区间上界，本版按**实测可达上界**重述问题与判据，不把"达不到的那一段"
     记成策略失败。
4. **无 DR ⇒ 策略不可直接部署**：本线产物是**能力基线**，鲁棒性是后续版本要逐项加回的变量。
5. **继承旧线 runner cfg**：旧线 PPO 一处改动会同时改本线；这是有意的同配方约束，但要在改动当时意识到。
6. **30 维动作与 102 维观测是新的尺寸**：checkpoint 与 UE 导出都按此宽度，跨族 checkpoint 不可互换
   （观测宽度不同即加载失败，这是设计而非缺陷）。
7. **头链与尾链的 PD 参数照抄旧线**（`150/10`）：新骨骼只在四条腿上加了轴，躯干链未动；若首跑出现
   头/尾振荡，先读探针的实际量级再判断，不凭现象改刚度。
8. **髋阶跃测试（评审 #6 更正）**：髋执行器驱动的是**整条下游链**，其有效惯量**不是** dummy link 的 `1e-6`；
   微小惯量只可能影响数值条件，**不能**据此推断"PD 必然过硬"。阶跃测试保留，记录**超调、稳定时间、限幅、
   时间步敏感性**。`*_kfe` 无碰撞形状这件事要说清两层：**"没建碰撞形状"**（几何缺失）与
   **"惩罚列表保留了一个永不触发的条目"**（`undesired_contacts` 里的 `.*_kfe`）是两个问题，
   后者不能靠删条目了事——要么补碰撞形状，要么在 yaml 里说明为什么保留。
