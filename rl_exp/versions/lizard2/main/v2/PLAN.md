# main/v2 方案（单变量：脚板动作权限；短骨架）

> 本版由 v1 复制而来，**唯一变化**是脚板（blade）四个关节从动作接口里去掉：配方元素表与 v1 相同，
> 差异全在 yaml ⇒ 按 versioning.mdc §A 用简短骨架。完整差异与逐项理由以 [diff.json](diff.json) 为准，
> 本文不复述逐项路径；读数归 `acceptance/records/`，结果回填见 [NOTES.md](NOTES.md)。

## 目的与假设

目的：判断**脚板的策略动作权限**是否在拖累步态（滑移、承重分配、脚板姿态）。**不是**判断脚板驱动
强弱是否合理 —— 那一问（候选弱增益）已由 `acceptance/records/2026-09-23-lizard2-v1-gait-skate.md`
的 ⑬⑭ 否掉，本版脚板沿用 v1 的增益、默认平放目标与上限。

假设（都可被本实验否掉）：

1. 脚板的策略动作权限是滑移 / 踮脚的成因之一。
2. 去掉权限后滑移下降，而速度跟踪与存活不退化。
3. 没有策略命令时，脚板仍能被 PD 稳定保持在默认平放位附近承重。

必须同时看的反向假设：去掉权限等于拿掉一个**饱和执行器**（⑫：承重期脚板常整段顶在上限），步态可能
因此**变差**；⑭ 已给出接口层先验 —— 把脚板目标钉住会让 v1 的策略在 1–3 秒内倒地。

## 差异清单（唯一变化）

`action.joints` 声明腿组不含脚板 pattern ⇒ 动作 **30 → 26 维**（观测的 `actions` 项宽度随之下移）。
脚板执行器（增益 / 阻尼 / 上限）、默认平放目标、奖励、终止、命令窗口、sim、训练预算**逐字沿用 v1**。

## 验收

**两臂与公平性**

- 实验臂 = 本版（26 维）。对照臂 = **v1 在当前资产上的重训**（同任务 id、配方逐字不变 ⇒ 不是配方变更，
  只是新 run）。**历史 checkpoint（`lizard2_v1/2026-09-22_19-26-50`）只作背景**：它训练用的脚板 hull
  与当前树不同（`acceptance/records/2026-09-28-lizard2-foot-hull-and-asset-isolation.md`），与实验臂
  不同源 ⇒ 在对照臂重训完成之前，本版的任何"改善"只能叫**机制读数**，不能叫因果。
- 两臂：同一份 eval 协议、同一承重门、同一起落过渡剔除规则、同一滑移口径、**配对 seed**、同预算。
  首轮 1 对 seed 排查机制与明显失败；若改善，再加多个配对 seed 检验是否稳定。

**评测窗口与样本下限（预先要求）**

- 命令固定 0.5 / 1.5 / 2.8 m/s，初态与评测方式两臂一致。
- 每档、**每只脚**至少覆盖 **30 个有效稳态承重周期**（"稳态" = 去掉起落过渡后仍保留中间帧的承重段）；
  不足的格子标**样本不足**，不进结论（⑭ 就是这么处理那批 0–4 周期的格的）。窗口长度按这条反推，
  不按墙钟时间定。

**读数（两臂同列）**

接触点滑移、承重分配（逐脚 duty 与承重占比）、脚板姿态（倾角、贴地占自身 cap）、**请求力矩与交付力矩**
（交付 = `clamp(请求, ±上限)`，是上界不是实测值）、饱和帧占比、速度跟踪、存活。

**预写判据（结果出来前写成这样，事后不改）**

| 结果 | 判定 |
|---|---|
| 滑移改善，且跟踪与存活不退化 | 支持"取消脚板策略权限" |
| 滑移下降，但机器人变慢或更易倒 | **不算改善** |
| 脚板仍整段饱和，或步态更差 | 查"固定参考 PD 是否阻碍接触顺应"（不是"策略乱命令"：⑭ 已证饱和可以来自策略自己的命令） |
| 交付力矩也明显下降 | **再看 rr 是否比 rl 改善更多**（⑫ 的错配：饱和重的是 rr、滑移重的是 rl）；单凭总滑移下降**不能**确认因果 |

## 启动方案（计划命令）

两个任务 id：`Lizard2-Flat-v2`（训练）/ `Lizard2-Flat-Play-v2`（回放）。两臂配对 seed、同预算：

```
python scripts\reinforcement_learning\rsl_rl\train.py --task Lizard2-Flat-v2  --seed <S>
python scripts\reinforcement_learning\rsl_rl\train.py --task Lizard2-Flat-v1  --seed <S> --max_iterations 14000
```

预算取 **14000**（= v1 实跑过的那个数），并**声明在 v2 的 runner cfg 里**（v1 的 runner 声明 10000 ⇒ 对照臂
那次重训因此带一条与 v1 首跑同类的偏离，写进它的 NOTES）。这样 v2 那次训练可由它自己的 NOTES 复现。

（开训前工作树必须干净 —— `run_manifest.begin` 硬拒；本版冻结后打 tag `lizard2-v2`。seed 与预算在开训
那次一并写进 NOTES 的"实际执行与偏离"。）

## 风险与挂账（预注册）

- **几何混淆**：对照臂重训之前，两臂差异里混着"训练时的脚板 hull 不同"。
- **接口改变**：动作维度改变即部署接口改变，UE 侧接不接不在仓内，本版只把变化递过去。
- **另一条优化轨迹**：26 维与 30 维的优化路径不同，"滑移下降"可能只是盆地差异 ⇒ 必须多 seed。
- **观测宽度**：`actions` 项宽度变化使本版与 v1 的观测宽度不同，而协议批准锚按 (协议, 资产) 记宽度
  ⇒ 处置见 [work/active/lizard2-v2-foot-authority.md](../../../../work/active/lizard2-v2-foot-authority.md)。
- **三档都在命令窗口内**：本线 `lin_vel_x` 是 `[0.0, 3.0]`（2026-09-22 当天由 0–2 放宽，见 yaml 注释），
  所以 2.8 档不是外推档；但注意 v1 的 runner 文档串与 v1 的 NOTES 仍写"0–2"（陈旧，NOTES 属冻结目录不改写），
  引用窗口时以各版 yaml 为准。
