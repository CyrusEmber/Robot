# lizard2 v1 步态实测：接触与载荷口径成立，两个关键量先误读、后补测（2026-09-23）

## 适用范围

本条记录**一次观测、它引出的判据缺口、一次自我更正，以及更正后的补测**：
`ablation_harness/protocols/lizard2_flat_v1.json` /
`lizard2_flat_v2.json` 的 `gait_swing_v1`（缺少离地高度项）与 `report_only` 里确实无人计算的
`foot_slip_mps`/`foot_yaw_deg`/`dof_torque_frac_of_limit`、`rl_exp/versions/lizard2/main/v1/PLAN.md`
验收节要求的 `min_lift_m`。修复形态与奖励侧改动另立（见末节）。

**更正（2026-09-23，同日复核）**：初版把探针的两个读数当成了"脚底净空"与"接触点滑移"，并据此写标题与
"决定性读数"。复核探针源码后**撤回**这两条定性（明细见"更正与撤回"）；下文凡涉及这两个量的位置一律
标为"未测"，直到 ⑤ 用新探针在同一 checkpoint 上补测、⑥ 把成因分开。本记录因此有四个状态：
初版、撤回后、⑤ 之后、⑥ 之后，引用时先看是哪一段。

## 验收条件

1. 结论必须来自**量**，不能只来自"看起来像"：逐脚 duty、承重期足端滑移、摆动期离地高度三样各给数。
2. 必须区分"真的抬了"与"力抖动"：`foot_contact == 0` 的帧要同时给几何读数。
3. 必须与**本仓既有的同一病症标准**对照（退役线自己的 `foot_clearance` 与 `r_slip` 升级记录），
   否则"0.2 m 算不算高""0.7 m/s 算不算滑"没有出处。
4. 判在**真·无限平面**上：有限地板上的长距离直行会掉出去，掉下去的行不许当读数。
5. （更正时补）**量与量必须同口径才能对照**：脚底净空 ≠ 足端原点相对自身最低点，
   接触点切向速度 ≠ 足端刚体速度。

### ③ 出处：本仓自己的同一病症标准

- `rl_exp/versions/lizard/REWARDS.md:18,41,45`：`feet_slide`(r_slip) = `−Σ_{接触脚}|v_f|²`，
  "**反划脚**：脚踩地就不许横移——逼'先抬再走'"；`foot_clearance`(r_fc) = "摆动脚离地不足
  **0.2 m** 罚"，两项**成对**即"步态时序的执法者"。
- `rl_exp/versions/lizard/main/v15/main_params.yaml:262-270`：v8.1 预注册升级，`r_slip` −0.003 → **−0.03
  （×10）**，触发条件写的是"`feet_slide` 停在噪声底、反解 `sum(|v_f|²) ~ 0.93/step`、低速**划脚**
  （v3 paddle-creep，**GUI 已确认**）以 **~0.7–1 m/s** 滑接触脚而跟踪只花 1/180 的价"。
  ⇒ 这条升级线**是**同病症的既有标准，但**本次没有与它同口径的读数**（探针给的是足端刚体速度），
  所以引用到此为止，不下"落在区间内"的结论。
- `rl_exp/versions/lizard/baseline/v1/PLAN.md:125` 预注册风险第 3 条：
  "**删掉 `feet_slide`/`foot_clearance`** 可能重现拖脚/划脚；**这是首轮主动接受的取舍**。"
  lizard2 v1 逐项照旧线冻结（`lizard2/main/v1/diff.json`、7 项奖励）⇒ **该取舍已到期**。

### ④ 判据缺口（本次能确认的那一半）

- `rl_exp/versions/lizard2/main/v1/PLAN.md:164` 的验收表格明写步态判据为
  `gait_swing_v1 {min_swing_feet, min_air_time_s, min_lift_m, band_mps}`，且"每条摆动脚同时满足
  **离地高度**、持续离地、**落地后恢复承重**，并报告支撑期足端滑移"。
- 实际交付的两种 K 只有 `min_swing_feet` / `min_air_time_s` / `min_landing_load` / `band_mps`：
  **`min_lift_m` 没有实现**，`min_air_time_s` 定在 **0.1 s**，而实测零力段 88% 短于 0.2 s
  ⇒ 现判据贴着观测值的下沿，只问"有没有动一下"，不问抬多高、迈多远、接触点在不在滑。
- 冻结理由记在协议 `why_v1`："No lift term in the gait criterion. The record carries per-foot contact
  and load, not height..."——**这句话对判决帧记录本身成立**（帧里确实没有高度列），
  但正确处置是**给记录加列 + 新种类**，不是删判据。**冻结件不事后改字**：协议文件的 sha256 被报告
  pin 住（`eval.json` 的 `protocol_digest`），改字会让报告对不上文件 ⇒ 更正只记在本记录，由下一次
  协议版本的新 `why` 条承接。
- 与判决的关系：`pass` 八条**没有一条能看见**步态质量（八条读的是接触、承重、朝向、位移与速度）
  ⇒ 那份 `pass` 只证明"没倒、方向对、位移对"，不证明会走路。**这一条不受更正影响**。

4. **执行器部分跟不上**：跟踪误差随速度涨（2.8 档 hip 误差 p50 0.14–0.23 rad、hfe p95 至 0.51 rad ≈ 29°）

   目标角本身可能就把脚放在很低的位置。

### ⑥ 目标角 → 脚底高度：低速的贴地是**被命令的**（同一次 run，2026-09-23）

做法：`body_link_jacobian_w`（世界系，DoF 轴 = 6 个浮基列 + 30 关节列）乘关节**目标误差**
（`joint_pos_target − joint_pos`，前 6 列补零 ⇒ 读作"关节达标、基座未动"），再补上绕最深顶点的转动项
（`diag_metrics.target_vertex_delta`，一阶、单步、无接触，`ponytail:` 上限记在函数里）。
`pred` = 若该步关节达标，脚底会在哪。**起脚/落地帧的目标本来就在要地面**，所以除全摆动帧中位外，
另给"每次摆动实测最高那一帧"的对照（`peak`）。

**读数**

1. **低速档的"贴地"在目标层就成立**：0.5 档摆动最高帧的目标预测只有 2.4–5.2 mm（rr/rl），
   也就是说策略**要求**脚在这时候只离地几毫米 ⇒ 低速"垫着走"不是执行器没跟上，是**命令本身如此**。
   这一条把 ⑤ 第 4 条的"不能单独解释"补上了：执行器误差是真，但它不是低速净空的主因。
2. **高速档目标要求的高度正常**：2.8 档目标预测 33–109 mm，与实测同量级 ⇒ 该档剩余差才是跟踪
   （hip/hfe 误差 p50 0.14–0.23 rad）。
3. **一条腿在三档一致异常：lf（左前）目标预测为负**（−15.1 / −31.2 / −20.1 mm）——**2026-09-23 晚降级为
   待验证，理由见 ⑦ 第 8 条**（左右关节目标是镜像的、脚网格同形，而符号翻转来自预测的转动项）。
   若成立，它与 ① 的 duty（lf 0.64/0.46/0.31）同向，
   也与 ③ 里后腿滑移最重、前腿较轻的分工不矛盾（lf 是被按住的、rl 是被拖着的）。
4. **边界**：一阶且单步，`Δθ` 中等值 0.01–0.27 rad，误差本身不小；无接触约束 ⇒ 预测值为负应读作
   "目标要求入地"（求解器顶回去），不是真的穿地。三档各 1 env × 8 s。
5. **确定性**：同 checkpoint、同 seed、同命令**重跑一次，⑤⑥ 的读数逐位一致** ⇒ 上面的差异不是单跑侥幸。
   但产出记录的**仪器**不可全信：同参数的 3 env × 8 s 曾有一次在 ~step 250 猝死（退出码 1、无 traceback、
   未写报告），重跑未复现。⇒ 跑前先删旧报告，否则崩溃会让上一份 JSON 原地留着被当成新读数
   （本次重跑即按此做）。

**因此"目标本身就低"与"被执行器按住"已分开**：低速是前者、高速是后者（后者的误差里按"参考是否越限"
再分，见 ⑦ 第 8 条，但**不要**把越限读成接口缺陷）。**为什么**仍是空的：⑦ 把 lf 的两个候选
（"被限位按住"、"资产几何不对称"）削弱、⑧ 把 lf 那条读数撤回之后，剩下的是**接口允许限位外参考**
（⑦ 第 6、7 条，是否裁剪待独立证据）与策略为何学出这个目标（奖励侧），两者都不在本条记录的范围。

**读数**

1. **"目标被限位按住"不是 lf 的原因**：1.5 与 2.8 档**四条腿普遍越限**，2.8 档四腿 hip 与 hfe 的

   不是某条腿的病灶，lf 的负净空不能归给它。
2. **事实只有一句**：策略在 1.5–2.8 m/s 下发的**位置参考**系统性超出关节限位。（初版这里写"超出可达
   范围"，用语错了，见第 6 条——参考越限不等于关节到了那里。）

   为负"同向、同档。

   详见 `acceptance/records/2026-09-23-lizard2-leg-chains-not-mirrored.md`（该记录另报后腿对 rl/rr
   本身不镜像，与 rl 的稳态滑移是**相关性不是因果**）。
5. **lf 的成因**：已在 ⑧ 撤回（摆动中段实测净空三档高于 rf，符号翻转来自线性修正项）⇒ 本节的越限读数
   与 lf 无关；后续读一阶预测须区分相位与瞬时修正量。
6. **接口允许下发限位外的参考，但这不等于"接口有缺陷"**（2026-09-23 晚更正，初版把这两件事混为一谈）：
   `JointPositionActionCfg(scale=0.5, use_default_offset=True)` 没有 `clip`（`rl_exp/tasks/lizard2_env_cfg.py:102-107`）、
   agent cfg 的 `clip_actions` 为 `null`（train 与 play 都是，见 `lizard2/main/cfg_lock.json`）、策略头最后一层
   是无激活的 `Linear` ⇒ **`0.5` 只是名义尺度，从未定义动作范围**；限位是 hip ±0.60 / hfe ±1.20（`lizard2.urdf`）。
7. **为什么超出参考可能是有意的**：本线是位置 PD——`τ ≈ Kp(目标 − 实际) − Kd·实际速度`（本地实现把位置
   目标交给仿真里的**隐式 PD**，`isaaclab/actuators/actuator_pd.py:41`；本配方腿 `Kp=800`、`Kd=40`，
   见 `main_params.yaml` 的 `actuators.legs`）⇒ **更远的参考本身就是产生驱动力矩的手段**。
   示范算术（**不是实测**，只为说明机制）：髋上限 0.6 rad、当前 0.4 rad、以 2 rad/s 运动时，
   参考 0.7 rad 给 ~160 N·m，裁到 0.6 rad 只剩 ~80 N·m——**那时关节还没到限位**。
   ⇒ **"参考越限 ⇒ 控制接口有缺陷 ⇒ 该裁剪"这条推断不成立**；裁剪有可能直接砍掉能力。
   "按限位留余量裁剪"同样没有依据：那个"余量"也无出处。
8. **误差与越限的关系不能倒过来读**：越限帧的跟踪误差确实更大（hfe p50 0.14–0.48 rad vs 界内 0.03–0.26），
   但这是**构造性的**（参考更远，差就更大），**不能**据此说越限造成了步态问题；原始 `目标 − 实际` 也
   **不能**整体算作执行器能力不足——承重所需的位置差、动态滞后、限位外参考都在里面。
   ⇒ 结论收窄为：**接口允许限位外参考、`scale=0.5` 不定义范围；"是否裁剪"是一个需要独立证据的决定，
   现有读数既不足以支持裁剪，也不足以支持留余量裁剪。** 要决定它，只需围绕**已有的越限帧**回答三件事：
   (a) 实际关节是否**贴着限位、贴了多久**，还是仍在正常运动（现在的"参考越限比例"把这两种情况混在一格）；
   (b) 把参考投影回限位后**驱动力矩会变多少**，是否只是从一种饱和换成同一种饱和；
   (c) **实际部署控制器**是否接受限位外参考，还是会自行裁剪或拒绝——训练必须匹配真正的部署行为。
   其中 (a)(b) 可立刻从录到的关节序列算出（**已在 ⑨ 给出**），跟踪报告也可以先把"参考超出范围的部分"单列，
   **不必为了让误差读数变小去改控制器**；若证实长期顶限位、或部署端明确禁止限位外参考，
   再在新版本里约束参考并**从训练一开始就用同一条规则**。

### ⑨ 越限参考到底做了什么：贴限位时长与裁剪会拿走的力矩（2026-09-23 晚）

动机：⑦ 把"参考越限"收窄成一个待证据的决定。位置 PD 下**更远的参考就是产生力矩的手段**，所以决定它是否该裁剪，
只需围绕**已有越限帧**回答：关节是否真贴着限位（还是仍在正常走）、把参考投影回限位会少掉多少力矩、
部署端是否接受限位外参考。前两问本节能答，第三问不在本记录。

做法（逐关节）：`actual_at_stop_frac` = 实际角距最近限位 < 0.01 rad 的帧占比，
`actual_at_stop_dwell_max_frames` = 其最长连续段；
`out_of_range_actual_at_stop_frac` = **只在参考越限的帧里**，关节同时贴住限位的比例；
`clip_removed_torque_p50_nm` = `Kp × |参考 − 投影回限位|` 的中位，**只统计"参考越限且关节未贴限位"的帧**
（关节已贴住时两种做法给的驱动相同）。`Kp` 与 `effort_limit` 读**实例化 cfg**
（`cfg.scene.robot.actuators["legs"]`：800.0 / 180.0），不手抄 yaml。

4. **因此现有证据不支持裁剪**，也不支持"按限位留余量裁剪"。与 ⑦ 第 6 条合起来：本 run 里这更像
   **位置 PD 下用远参考换力矩的正常用法**，且没有可归因的伤害。要改仍只有两条正当理由：
   (i) **部署端不接受限位外参考**（问题 (c)，属部署链路，本记录不含）；(ii) 后续证明它损害某项验收（目前没有）。
5. **边界**：`clip_removed_torque` 是**指令力矩之差**（`Kp × |参考 − 投影|`），不含阻尼项、也未做
   `effort_limit` 截断 ⇒ 它是"裁剪会拿走多少"的上界读数，**不是**最终关节力矩；`at_stop` 的 0.01 rad
   容差是取定的，改容差会移动 `out_of_range_actual_at_stop_frac`（"贴住"的定义在这里）。
