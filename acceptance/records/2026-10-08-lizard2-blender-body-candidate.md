## 验收条件

### 默认参考姿态要求

方向从近端关节指向远端关节；以机体向头为前、向尾为后、体侧为外展，世界地面另标定。

| 骨段 | 要求 | Blender 端点，按名称查找 |
|---|---|---|
| 前上段：上臂 | 朝后、向侧方外展 | `lf/rf_haa.head` → `lf/rf_hfe.head` |
| 前下段：前臂 | 朝前、倾斜，不竖直落下 | `lf/rf_hfe.head` → `lf/rf_kfe.head` |
| 后上段：股骨 | 朝前、向侧方外展 | `rl/rr_haa.head` → `rl/rr_hfe.head` |
| 后下段：小腿 | 朝后、倾斜，不竖直落下 | `rl/rr_hfe.head` → `rl/rr_kfe.head` |

这是用户确认采用的工程默认姿态要求，不强制整个步态周期保持同一方向。“比较平行地面”没有量测角度，不硬填数值。前后腿分别设计，只镜像同一对左右腿。

### 操作步骤

1. **打开源件，另存候选。** 输入为 `E:/Robot/rl_exp/blender/lizard_stance.blend`。另存为 `E:/Robot/rl_exp/blender/lizard2_stance_candidate.blend`，本轮保留原输入。`source/lizard.blend` 不是当前导出管线输入。先确认实际头尾、左右与骨骼命名一致，记下骨架对象变换，区分世界坐标和骨架局部坐标。

2. **认清关节中心和网格归属。** 展开 Armature 与网格父子关系，按上表找到端点，核对各刚性网格的 `parent_bone`。导出后的 `hip` 与 `haa` 共位，`hip` 由导出器添加，不要求在 Blender 另造关节。当前导出器读取 `arm.matrix_world @ bone.head_local`，不能只改显示用的 bone tail。

3. **先调一侧前腿与一侧后腿的长度。** 用骨架 Edit Mode 调真实关节中心，同时调整对应关节网格和骨段网格的位置/尺寸。上段长度取 `haa.head→hfe.head`，下段取 `hfe.head→kfe.head`；足段还须检查 `kfe.head→foot.head` 与实际足底网格。以躯干尺度为参照，记录所选骨长和比例，没有动物依据就写工程选择。不要只拉长显示骨骼而不移动下游关节中心，也不要假定骨架会自动拉长刚性网格。

4. **摆出上表腿形，调体高与足底位置。** 在 Edit Mode 落实静止几何；Pose Mode 可预览，但只存姿态旋转不会改变当前导出器读取的静止 head。默认足底朝下，检查实际足底而非 foot 原点是否接地。侧视看前后折叠，正视看外展与体高，俯视看腿根和落脚位置；逐块核对网格仍贴合关节，没有双重移动或拉断。

5. **镜像到另一侧。** 以前后躯干的机体中面为基准，前腿镜像前腿、后腿镜像后腿；骨架对象带旋转时，不能直接对局部坐标某一列反号。同步处理关节中心、骨段网格、脚掌、父子关系和命名，检查负缩放与法线。不要假定自动命名识别现有 `lf/rf/rl/rr` 前缀。按对应关节中心与骨长检查镜像，不只看截图。

6. **保存并交回。** 在 Object/Rest 状态复核，保存候选 `.blend` 和侧视、正视、俯视截图；在结果节回填实际路径、骨长、镜像检查与接触/碰撞观察。Codex 接手后核对导出、转轴、运行时初始角度，再进入限位设计。

### 完成时如何判断

- 用户检查候选是否符合上表腿形、外形是否接受；不符合就继续修改，不能以“能走”代替腿形。
- 同对左右腿的关节中心经机体中面反射后对应、骨段等长，网格和父子关系同时对应。记录检查方法与实际残差；没量的项目留未核验，肉眼对称不算数值核验。
- 默认姿态的实际足底能放到同一地面，骨段与躯干无明显互穿。找不到兼顾腿形与接地的候选时，保留失败姿态和原因交回 Codex，不靠扩大限位或删目标掩盖。
- 重新打开候选后，静止骨架和网格保持一致，截图与文件对应。Blender 检查不等于导出碰撞、承重或动力学通过。

### 动作通道决定

用户拍板（2026-10-08）：踝部只取消策略动作通道。按现有腿链映射，范围为四条腿的 `*_kfe_joint` 与 `*_foot_joint`；前肢对应腕/足端，后肢对应踝/足端。它们仍是可动关节，保留 PD 驱动机制；不改成 fixed，不删骨骼，不用 Blender 的旋转锁代替动作配置。

正式 v3 配置中，对应关节不进入 `action.joints`，也不留无效动作占位。未接收策略命令时，位置目标须为本版 `default_joint_pos`；新静止几何下默认角仍需核对，不能以“取消通道”替代默认目标设计。本次决定不顺带改 PD 增益、力矩/速度上限或机械限位。

当前 v2 的动作列表已不含 foot、仍含 kfe；若其余接口不变，v3 从 v2 继续去掉四个 kfe 通道，预计动作维度由 26 变为 22。物理关节数量不因这项动作配置改变而减少。此处是接口设计预期，不是已运行读数；最终由配置构建与运行时布局核验，含 last-action 观测、部署映射及默认目标复位。

验收时须同时看到：策略无对应通道、执行器仍存在、未命令关节目标与版本默认角一致、实际关节可在接触载荷下偏离目标。恒定目标不保证实际关节锁死，也不保证足底全程水平；接地、滑移与承重仍按实际运动检查。

**髋单轴在默认姿态下的水平位移（**不是推进能力**，用户 2026-10-08 更正）**：`|dp/dq|`（髋）= 髋竖轴每转
