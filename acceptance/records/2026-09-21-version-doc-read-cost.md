# 版本记录读取成本（A/B 两读法，baseline/v1）

## 适用范围

覆盖一种任务：拿 `baseline/v1` 回答四问——**改了什么 / 相对谁 / 实跑是什么 / 证明了什么、不证明什么**。
两条读法：

- **A（摘要 + 链接）**：起点 `v1/NOTES.md`，沿它给的链接取 `diff.json`、`base.json`（按需 `PLAN.md`）。
- **B（只有声明）**：起点 `v1/diff.json`，可读 `base.json`、`PLAN.md`，**禁读任何 `NOTES.md`**。

读者 = 两个**全新上下文的独立读者**（互不见对方，也无本次会话的记忆），故两臂均无污染。
时点 2026-09-21，靶为 `v1.2` 形态的 NOTES。

不外推：不含其它版本、不含"开新版"或"改代码"任务的读取成本、不含人工读者。

## 验收条件（读数前定）

- **计数单位**：读到的文件内容按 UTF-8 字节计**整份**（读者读了全文即计全文）；打开文件数按实际打开计。
  两臂的字节数由主会话按 `st_size` 精确折算——两读者都无 shell，自估数一律不采信（见「证据引用」）。
- **完成条件**：四问都必须有答案。任一问答不出即该臂**未完成**；"更省但答不完"不算更优。
- **判据**：A 完成且不比 B 显著更贵 ⇒ 摘要 + 链接成立；A 必须回正文才答得出，或 B 能完成而 A 更贵
  ⇒ 降级为"短摘要（阅读提示）+ 链接"并记下天花板。

## 结果

**精确字节**：`NOTES.md` 15568 / `PLAN.md` 13668 / `diff.json` 7122 / `base.json` 364。

| 臂 | 实际打开 | 字节 | 四问完成度 |
|---|---|---|---|
| **A** | `NOTES.md` + `diff.json` + `base.json`（3 份） | **23054** | **4/4**（`PLAN.md` 只在对奖励权重/阈值口径时有增益，非必需） |
| **B** | `diff.json` + `base.json`（2 份，纯声明即可） | **7486** | **2/4**——Q1 ✓ Q2 ✓，Q3 ✗、Q4 的"结果"半部 ✗ |

**两臂差异是信息归属，不是成本**：

- Q3 在 B 侧**结构性地无解**：`PLAN.md` 自己把结果外链到 NOTES（`PLAN.md:4`），`PLAN.md:109` 只有带
  占位符 `<model.pt>` 的示例命令 ⇒ 读者明确回"答不出"。
- Q4 的**判据与边界**在声明侧齐（阈值、`smoke_only` 口径、预注册挂账都在 `PLAN.md`）⇒ 只有
  "跑了没有、通没通过"缺。**B 少读的 15568 字节里没有一条是冗余**。
- A 侧读者自陈：`重点变化` 段**只够粗答**，逐路径清单仍须 `diff.json`；run id、`model_5850.pt`、
  seed 123 只在 NOTES——这正是"摘要 + 链接"分工成立的证据（摘要给定位，声明给完整性）。

**决定 (a)：保留 1–2 句重点变化，撤掉其完整性承诺。** 依据：A 在一个文件内定位到四问的全部坐标，
而读者自陈仍需 `diff.json` 补逐路径——与 §A-2 现写法一致。反面（只有链接）被 B 侧证否：省 3.2 倍字节
但答不完。

**决定 (b)：不做措辞闸门。** 依据：根因是复制继承与修订失联，已分别由 §A-1（copy 后重置正文）与
§B-6（差异集合变了改声明）承接；而全版本措辞禁令会误伤有明确范围的合法事实（"本次修订中奖励项零变更"），
且与"冻结历史不改写"冲突。**重议触发保留**：再开两个新版本后若仍出现全量句失真（清单已由 `diff.json`
承担却仍在 NOTES 里复述），把闸门议题重新提出。

**新发现的缺口（已另立事项）**：**实跑命令行在四份文件里都不存在**——A 侧也只能引"运行记录"，而 run
记录的落点在 log dir 目录外，读者沿链接走不到。故 §A-2 的"实跑引 run"目前在读者侧是死链，见
`work/active/run-record-reachability.md`。

## 证据引用

- 精确字节：`python -c "... f.stat().st_size ..."` 对四个文件取整份大小（两读者无 shell，其表内自估数
  已按口径弃用，只采信其读取范围与答案）。
- 两臂读者各自的四问答案与文件表：本次会话的两个独立读者返回（A 臂自陈 (a)(b) 两行在案）。
- 口径来源：`acceptance/records/2026-09-20-doc-read-cost-baseline.md`（计数单位与"入口必读整份"约定）。
- 规则侧：`.codemaker/rules/versioning.mdc` §A 步骤 1/2、§B 第 6 条。
- 相关事项：`work/closed/2026/version-doc-single-owner.md`（本记录即其关闭读数）、
  `work/active/run-record-reachability.md`、`work/active/ledger-inbound-reference-scan.md`。

## 未覆盖边界

- **只两个读者、只一个版本**（`baseline/v1`，且是 lineage root）：无统计意义，不得外推为"链接版对
  所有版本都够"。
- 读者是 AI（无 shell、无搜索引擎），**不是**真人读者；字节口径可复现，但"谁更快"在人工侧未测。
- 未测"摘要写得更短/更长"的中间形态，未测 v2 类**多变量**版本（其 NOTES 摘要与声明差得更远）。
- 未测 run 记录链接修好后的读数（那会改变 A 臂 Q3 的成本与完成度）。
- 两读者自估的字节数不可复现，本记录只用主会话的 `st_size`。
