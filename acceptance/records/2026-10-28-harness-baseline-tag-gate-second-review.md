# Harness 基线标签闸门第二次独立复审（2026-10-28）

## 适用范围

不带执笔历史的新上下文审核基线标签闸门当前实现及证据，仅核查本地标签名称与文档声明。

## 验收条件

基线声明和 Git 失败诊断准确，原破坏测试及新增回归通过独立审核。

## 结果

不通过。真实 CLI 可将 HTML 注释内的旧声明当作可见基线，掩盖正文中无法解析的新声明；违反基线声明准确的关闭条件。修复和证据变化后须重新独立审核。

- 真实仓默认检查和 `--self-test` 均退出 0；自测末行为 30 fixtures。复跑执行记录中的隔离测试，原缺标签、缺冒号及点、连字符后缀破坏均按预期失败，恢复后通过。隔离仓复制本地标签名称，不验证标签指向或远端。
- 独立隔离破坏：正文基线改成无冒号的 `v9.9.9`，保留 `<!-- **代码基线**：v1.11.0 -->`；默认真实 CLI 仍退出 0，输出 `VERSION_DOCS_OK`。实现见 `rl_exp/tools/verify/check_version_docs.py` 的 `baseline_tag_problem()`；未区分注释和可见内容。
- 清空子进程 `PATH` 后真实 CLI 退出 1，报 Git 无法读取，不误报标签缺失。空标签集合、夹具自身破坏和隔离套件调度失败传播均按预期。`hooks/pre-commit` 调用默认模式，套件以 `--self-test` 调用并按退出码传播。
- 平台默认编码下 `_git_tags()` 的解码异常未被捕获；注入 `UnicodeDecodeError` 会产生 traceback，尚未复现真实 Git 标签触发。自测成功末行改变可能影响未知的外部调用者，仓内套件按退出码判定。
