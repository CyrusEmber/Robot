# 论文总结格式模板

## 〇、模式选择

- **标准模式（默认）**：下文一、二、三节全套。
- **精简模式**：用户说"精简总结 / 简版 / 简要总结"时启用，只输出下文四节内容，一、二、三节跳过。

## 一、12 点结构化字段表

以表格输出，字段顺序固定，一行一字段：

| 字段 | 填写指南 |
|---|---|
| 链接 | arXiv abs 链接（先核对 ID 与标题一致，不符要纠错） |
| 论文名 | 完整英文标题，含副标题 |
| 年份 | 首发/发表年份，附 venue（会议/期刊，Oral/Spotlight 可注明） |
| 方向 | 一级技术方向，英文短语，如 Multi-behavior Locomotion |
| 核心问题 | 论文解决什么问题，一句话说清痛点 |
| 核心方法 | 关键技术路线，列出核心机制/创新点，多个用顿号隔开 |
| Input | policy/系统的输入：状态 + 指令，概括来源即可 |
| Output | 输出粒度：关节力矩/关节位置/高层动作指令 |
| Policy | 单策略/多策略/分层；训练范式（RL/IL/蒸馏/端到端）；仿真环境 |
| Perception | 感知模态：proprioception / 视觉 / 深度 / 外感受，注明"无视觉"等关键取舍 |
| 能力 | 实际演示的行为与泛化表现，逐项列举，不夸大不脑补 |
| Game Friendly | 高/中/低 + 一句话理由，评级标准见下 |
| 我的结论 | 对当前游戏项目的可借鉴点与取舍，一两句话 |

### Game Friendly 评级标准

- **高**：方法可直接落地游戏 locomotion/动画/角色控制（如 motion matching、状态机可直接复用的结构）。
- **中**：理念可借鉴但需大改造，或依赖真实物理/sim-to-real 流程，游戏只需其骨架。
- **低**：纯机器人学/硬件导向，游戏仅可参考思想。

## 二、详细总结结构（七段）

1. **背景与动机**：领域现状、痛点、论文要解决什么。
2. **方法详解**：核心机制拆解，必须写到可复现粒度，逐项覆盖：
   - **训练管线**：分几阶段（如 teacher RL → student 蒸馏），每阶段输入/损失/算法；
   - **观测空间**：逐项列出本体感知、外感受、指令、特权信息各通道，采样细节（如高度采样点数/半径）能查到就写；
   - **动作空间**：输出什么粒度（力矩/关节位置/相位残差等结构化参数）；
   - **reward**：逐项列举任务项与正则项，不写"等若干项"；
   - **噪声与随机化**：逐项列出——物理参数随机化、观测噪声（哪些通道、什么形式、什么作用域）、初始化随机化、外感受退化模拟（如遮挡/漂移/失效三档条件及比例）、退火与课程策略；
   - **网络结构**：encoder/policy 模块构成与尺寸；
   - **curriculum**：地形课程、噪声课程、reward 权重课程各是什么。
3. **实现与部署细节**：仿真器、算法、并行规模、控制频率、机器人平台、传感器、关键工程点。
4. **实验与泛化结果**：主要结果（数字优先）、零样本泛化场景、对比基线、消融。
5. **局限与风险**：论文自述 + 读者视角的弱点。
6. **与当前 SOTA 的对比**：结合网络搜索核实该方向当前 SOTA，回答"这篇论文今天还剩多少价值"——哪些结论已被超越或修正、哪些机制被后续 SOTA 吸收、SOTA 视角暴露的本文盲点。例：Learning by Cheating 对上 LEAD / TransFuser v6——新工作证明 privileged expert 仍有用，但暴露 learner–expert asymmetry（expert 能看到学生因遮挡/不确定性物理上看不到的东西）。凭记忆写的 SOTA 事实标"（待核实）"。
7. **对游戏开发的启示**：结合 Game Friendly 评级，落到具体可借鉴点与"不该照搬什么"，与"我的结论"呼应。

> 方法段宁细勿粗：训练配方、噪声模型、reward 项是后续复现与借鉴的直接依据，论文正文/附录给出的都要收录；宁可长，不可糊。

## 三、写作规范

- 中文为主，术语保留英文原词（gait、policy、reward、domain randomization 等）。
- 每段聚焦事实，评价集中在"局限"与"游戏启示"两段。
- 不编造数值：网络尺寸、速度上限、训练时长等没核实到就写"待核实"。
- 引用论文措辞的关键概念时保留英文原名，如 Multiplicity of Behavior (MoB)。

## 四、精简总结模式

只输出以下六部分，不写实验过程、训练管线、实现部署细节：

1. **元数据一行**：论文名（英文原题）、年份 + venue、arXiv 链接。
2. **优点**：论文实际展示的核心贡献，逐条列。
3. **缺点与局限**：论文自述 + 读者视角弱点，逐条列。
4. **方法对比**：论文内与 baseline/相关方法的对比结论——赢在哪、输在哪，只写论文给出的对比结论，不展开实验设置。
5. **结果**：核心数字结论（成功率、指标提升、泛化场景等），没核实到的写"待核实"。
6. **与当前 SOTA 的对比**：结合网络搜索核实当前 SOTA，几条说清"这篇论文今天还剩多少价值"——哪些结论已被超越或修正、哪些机制被后续 SOTA 吸收、SOTA 视角暴露的本文盲点（例：Learning by Cheating 对上 LEAD / TransFuser v6 暴露的 learner–expert asymmetry）。凭记忆写的标"（待核实）"。

写作规范沿用第三节；优点/缺点不加解读性标签，解读须标"（解读）"。

## 五、papers/ 入库结构

```
papers/
  INDEX.md                      # 分类索引：每篇一行（论文名链接 | 一句话概括 | 要点）
  <论文名短横线>/
    brief.md                    # 必存
    detail.md                   # 可选，仅用户要详细总结时生成
```

- **INDEX.md**：按分类分节（Locomotion / Navigation·Driving / 游戏AI·其他），每篇一行表：`| [论文名](链接) | 一句话概括 | 要点 |`。
- **brief.md（必存）**：= 精简模式六部分，开头加两块——**一句话概括**与**要点**（3~5 条）；在"结果"与"SOTA 对比"之间插入**极简 Input / Output / 实现**，各一行：
  - `Input:` 观测 + 指令来源（如 proprioception + 高度采样 + 速度指令）
  - `Output:` 输出粒度 + 控制频率（如关节位置目标 @ 50Hz）
  - `实现:` 算法 + 仿真器 + 并行规模（如 PPO + IsaacGym 4096 envs）
- **detail.md（可选）**：只写 brief 没有的内容——方法详解（可复现粒度：训练管线、观测/动作空间逐通道、reward 逐项、噪声与随机化、网络结构、curriculum）、实现与部署细节、实验与泛化过程、对游戏开发的启示。优缺点、结果数字、SOTA 对比、Input/Output/实现概要均在 brief 中，不重复。
