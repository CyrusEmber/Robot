# Paper Summarizer（论文调研笔记）

把论文压缩成统一格式的调研笔记，便于多篇横向对比，直接服务游戏开发决策
（locomotion / 动画 / 角色 AI 选型）。

## 模式

- **标准模式（默认）**：12 点字段表 + 七段详细总结（含 SOTA 对比段），见工作流程 3~6
- **精简模式**：用户说"精简总结 / 简版 / 简要总结"时启用。只输出：元数据一行
  （论文名、年份 venue、链接）+ 优点 + 缺点与局限 + 方法对比 + 结果（核心数字结论）+
  与当前 SOTA 的对比。不写实验过程、训练管线、实现细节。规范见
  `references/format-template.md` 精简模式一节

## 工作流程

1. **获取论文**：元数据（标题 / 作者 / 年份 / venue）以 arXiv abs 页为准；需要正文与附录
   细节（网络尺寸、reward 逐项、噪声配置等）时抓 TeX 源码 `https://arxiv.org/src/<arxiv_id>`
   （tar.gz，解包后定位 main.tex 递归读），比 PDF 可靠且能拿到附录。abs 页信息不足时补抓
   项目主页或搜索结果。**PDF 直抓常失败，不要依赖 PDF 链接**
2. **元数据核对（强制）**：标题 / 作者 / 机构 / 年份 / venue 必须以 arXiv 或官方页面为准，
   不得凭记忆填写；arXiv ID 与论文名不符时必须向用户指出并给正确链接；年份以首发为准，
   附 venue，Oral/Spotlight 可注明
3. **填 12 点字段表**：字段定义与填写指南见 `references/format-template.md`，先读它
4. **写详细总结**：七段结构（背景与动机 / 方法详解 / 实现与部署 / 实验与泛化 / 局限 /
   与当前 SOTA 的对比 / 对游戏开发的启示）。方法详解必须写到可复现粒度：训练管线分阶段、
   观测与动作空间逐通道、reward 逐项、噪声与随机化逐项（含作用域与课程退火）、网络结构
   尺寸 —— 正文和附录给的都要收，宁可长不可糊
5. **SOTA 对比（强制，两种模式都做）**：结合网络搜索核实该方向截至当前的 SOTA，回答
   "这篇论文今天还剩多少价值"：哪些结论已被超越或修正、哪些机制被后续工作吸收沿用、
   SOTA 视角暴露的本文盲点。**搜索核实的与凭记忆写的 SOTA 事实必须区分**，后者标
   "（待核实）"
6. **我的结论**：基于论文内容给出"对当前游戏项目可借鉴什么、不该照搬什么"；用户已写结论
   时以用户的为准，可帮其校验是否有论文事实支撑
7. **入库（可选）**：存入仓库根 `papers/`（结构见模板文件第五节）：`brief.md` 必存，
   用户要详细总结时再生成 `detail.md`（只写 brief 没有的可复现细节）；同时在
   `papers/INDEX.md` 对应分类下加一行（论文名链接、一句话概括、要点）。**入库前先读一篇
   现有 brief 对齐粒度**

## 输出规范

- 中文为主，专业术语保留英文原词（gait、policy、proprioception、reward shaping 等不硬译）
- 术语优先用论文原文措辞；自己加的解读性标签（"XX 式"、"类似 XX 机制"）必须显式标注
  "（解读）"
- 每个字段一句话说清，不堆砌；12 点用表格输出
- "能力"字段只列论文实际演示的行为
- 数值类事实（网络结构、速度范围、机器人型号）必须核实；不确定标"待核实"，**禁止编造**
- 直接引语必须来自本次实际抓取的内容；凭记忆复述的"原文"（尤其补充材料/附录）必须标
  "（凭记忆，待核实）"，与已核实引文严格区分
- **总结新论文前先读 `references/` 里的完整示例**，对齐粒度与口吻
