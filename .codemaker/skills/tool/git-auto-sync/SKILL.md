# Git Auto Sync（迭代完成自动更新云端）

**默认行为：每完成一次工作迭代（改动闭环、结果回填、版本冻结），
自动 commit + push，不需用户再次催促**——这正是本 skill 存在的目的。
commit 内容要向用户汇报；推送失败报告原因，绝不强推。

仓的实例事实（路径/远端/当前版本）以各仓 `README.md` 与项目文档为准，
本 skill 只载方法与纪律。

## 核心循环（每次迭代收尾执行）

```
1. git status + git diff --stat          # 审查：改了什么，是否该提交
2. 分组提交（见粒度节），写规范 commit message
3. git push（有 tag 时 git push --tags）
4. 向用户汇报：提交哈希 + 一句话内容 + 远端状态
```

自动触发点（满足其一即执行，无需请示）：
- 代码/配置/文档改动闭环（修完 bug、加完功能、改完参数）
- 版本冻结（任何"冻结"语义工件：参数版本、评测协议版本）
- 记录回填（训练结果、eval 跑分、NOTES/报告更新）
- 用户明说"提交/同步/推送"

不触发：改动半途、讨论中、用户明说"先别提交"。

## 提交粒度与信息规范

- **一次迭代一组提交**：代码改动 / 文档更新 / 版本冻结分开 commit，
  不混成一坨；纯格式噪音（编辑器重排）单独或并入相关改动
- **message 格式**：一行摘要，说清"改了什么 + 为什么"，
  命令式语气（`Add X`, `Fix Y`, `Freeze vN: ...`），中英随仓库惯例
- **空提交禁令**：status 干净就报告"无改动"，不造空 commit

## 版本冻结 = commit + tag（锚点纪律）

适用于一切冻结语义的版本（训练配方 vN、评测协议 vN、数据集版本）：

```
git add -A && git commit -m "Freeze vN: <摘要>" && git tag vN && git push --tags
```

- 复现 = `git checkout vN -- <冻结目录>`
- 锚点之后的结果回填是正常提交，**不重打 tag**——tag 只钉冻结那一刻
- 已推送的 tag 不改指不改名；冻结内容错了 = 开 vN+1

## 安全纪律（推送 = 共享状态操作）

- **绝不** `--force` / `--force-with-lease` / 改写已推历史 / amend 已推提交
- 推送前扫一眼 diff：密钥、token、绝对路径泄漏、意外大文件（资产/数据集/模型权重）
- 无远端 → 一次性问用户要 URL；push 报错（网络/权限/非快进）→ 报告，
  不 retry 循环，更不强推
- 敏感实验代码默认建议私有仓

## 进仓 / 不进仓（通用判据）

| 进 | 不进 |
|---|---|
| 源码、配置、协议、文档 | venv / 环境目录 |
| 评测跑分、导出的指标 csv（记录即数据） | 原始训练产物（checkpoint/TB 事件文件） |
| 冻结版本目录（含 NOTES） | `__pycache__` / 编辑器缓存 / OS 垃圾文件 |
| 工具脚本 | 大体积资产二进制（另走 LFS 或制品库） |

新仓起步 `.gitignore` 至少挡：`__pycache__/`、`*.pyc`、venv 目录、logs。

## 布局模式：单一真身 + junction（Windows）

工作树与 git 仓同一份文件的零同步方案（已知案例：机器人训练包
真身在独立仓，宿主框架树内留 junction 指回，路径不变、工具链无感）：

- 真身只在仓内；宿主树内同名目录 = junction
- 宿主树自若是 git 仓，junction 目录进 `.git\info\exclude`（本地排除，
  防误 add 穿透链接）
- **删 junction 只准 `rmdir`**（只摘链接）；递归 del 会穿透删真身
- 报错里出现真身路径与链接路径混用 = 正常，同一文件

通用原则：**任何时刻一份真身**。要么仓即工作树，要么链接回接，
不接受"copy 双份靠人肉同步"。

## 常见坑

- CRLF 警告（`LF will be replaced by CRLF`）无害，跨平台协作再上 `.gitattributes`
- status 大量意外删除 → 先查是否误动真身（move/del），恢复用 `git restore`，别手补
- 宿主仓 status 冒出本该 exclude 的目录 → `.git\info\exclude` 被清，先补防护
- 首次 push 弹浏览器登录 = Credential Manager 正常流程
- tag 推送要显式 `--tags`（普通 push 不带 tag）
